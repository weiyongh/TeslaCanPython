# TM3-004 低速加速分析结论

## 1. 诊断问题与适用范围

诊断问题：车辆在D挡和 `READY/DI_systemState=ENABLE` 条件下，轻踩加速踏板后，正扭矩请求、实际扭矩、轴速、车速、电功率及动力电池输出如何建立，两个重复加速段是否一致。

适用范围：本结论仅适用于 `input/can_20260827135814_TM3-004_低速加速采集.asc`、当前车辆及 `input/tesla_model3_ONYX.dbc`。本次最高车速约12 km/h、踏板不超过5.2%，不代表中高速、大扭矩或热态能力。

## 2. 采集概况与实际动作

ASC总时长约149.6 s，共425,741帧。两次加速均从D挡静止开始：

| 阶段 | 第一次 | 第二次 |
|---|---:|---:|
| 挂入D挡 | 20.0296 s | 84.9058 s |
| `DI_systemState=ENABLE` | 20.0391 s | 84.9058 s |
| 松开制动 | 26.7167 s | 88.3415 s |
| 加速踏板首次非零 | 35.4578 s | 100.1333 s |
| 回P | 71.9552 s | 136.0413 s |

实际动作整体符合脚本。第二次准备阶段在81.821～82.369 s有一次短促制动动作，随后84.161 s重新踩住制动并完成挂D；它不影响100 s附近的第二次有效加速段，但应作为实际操作记录保留。

## 3. 正扭矩建立关键时序

| 观察量 | 第一次加速 | 第二次加速 |
|---|---:|---:|
| 踏板首次非零 | 35.4578 s，0.4% | 100.1333 s，0.4% |
| 扭矩请求首次为正 | 35.5593 s，8 Nm | 100.2552 s，8 Nm |
| 实际扭矩首次为正 | 35.5593 s，8 Nm | 100.2552 s，8 Nm |
| 踏板→首个正扭矩样本 | 101.5 ms | 121.9 ms |
| 车速首次超过0.5 km/h | 36.4996 s | 100.9563 s |
| 峰值踏板 | 5.2% | 4.8% |
| 峰值请求扭矩 | 442 Nm | 474 Nm |
| 峰值实际扭矩 | 454 Nm | 504 Nm |
| 峰值车速 | 11.84 km/h | 11.44 km/h |
| 峰值轴速 | 95.3 RPM | 92.7 RPM |

`0x108 / DI_torque`在本文件中约每100 ms出现一次，因此101.5 ms和121.9 ms是“从踏板变化到首个可见扭矩报文样本”的观测时延，不能直接当作逆变器内部真实控制延迟。请求与实际扭矩在同一报文中同步变化，本数据分辨率不足以量出二者内部的毫秒级执行延迟。

在正扭矩样本中，第一次 `实际−请求`平均约+2.1 Nm、平均绝对差约3.1 Nm；第二次约+4.9 Nm、平均绝对差约6.1 Nm。趋势和符号跟随良好。绝对扭矩值依赖当前DBC缩放，后续宜用更多工况交叉验证后再固化为车型正常范围。

## 4. 请求—条件—决策—执行—反馈—结果

### 请求

`0x118 / DI_accelPedalPos`两次均由0开始平缓上升，峰值分别为5.2%和4.8%，符合“轻踩加速”。

### 条件

- 两次加速时 `DI_gear=D`。
- `DI_systemState=ENABLE`，结合TM3-003结论，即车辆处于本车型CAN层面的READY/可驱动状态。
- 制动开关已经释放。
- BMS接触器保持闭合，充放电能力边界保持释放状态。

### 决策与执行

踏板请求出现后，`DI_torqueCommand`建立正扭矩；`DI_torqueActual`同步跟随。请求与实际扭矩继续升高后，`DI_axleSpeed`和 `DI_vehicleSpeed`由零上升。

### 电池与功率反馈

- D挡静止基线的 `BMS_packCurrent`约1.3 A。
- 第一次加速电流峰值约6.4 A，第二次约7.9 A；第二次较高的扭矩峰值对应较高的电池放电电流。
- `BMS_packVoltage`静止基线约347.9 V，加速窗口最低约347.30～347.32 V，呈小幅负载压降。
- `DI_elecPower`在起步后由0升至最高约2.0 kW，与低速轻加速的功率量级相符。
- `BMS_maxDischargeCurrent=682.624 A`、`BMS_maxChargeCurrent=250 A`及 `DI_sysDrivePowerMax=248`、`DI_sysRegenPowerMax=92`全程不变；实际需求远低于能力边界，没有观察到限扭饱和。

当前DBC下 `BMS_packCurrent`在正加速时为正、减速阶段可变为负，本采集域可暂按“正值放电、负值充电/回收”理解。

### 结果

两次实验均形成可重复的正常正扭矩闭环：

```text
D挡 + ENABLE(READY) + 制动释放
  → 加速踏板增加
  → 正扭矩请求建立
  → 实际扭矩跟随
  → 轴速上升
  → 车速上升至约11～12 km/h
  → 电池放电电流增加、Pack电压轻微下降
```

## 5. 系统边界与DBC冲突

### 可用于本次结论

- `0x118`：挡位、系统状态、加速踏板。
- `0x108`：后电驱扭矩请求、实际扭矩、轴速。
- `0x257`：电驱侧车速。
- `0x266`：电驱电功率。
- `0x132`：Pack电压与电流。实车帧为6字节，而主用DBC定义为8字节；目标电压、电流字段均位于前6字节，采用允许截断方式可稳定解码，但仍保留版本差异标记。
- `0x7AA`：约1 Hz可见的Pack/DC-link电压页；母线约347.7～348.5 V。

### 不可可靠使用

- `0x1D8 / DIS_torque`的公开DBC定义存在字段重叠；按当前定义强行展开得到满量程跳变等物理不合理结果，因此不能用于前电驱扭矩或轴速结论。本次只能确认后电驱链路。
- `HVP_shuntCurrentDebug`解码为固定异常值，且其多路复用/版本一致性不足，不作为实际Pack电流；本次以 `0x132 / BMS_packCurrent`为准。
- `0x7AA`存在DBC未定义的多路复用页7；这些帧不应套用已有页定义。
- `DIS_a154_resolver=0`只表示未广播旋变告警；仍未获得旋变实时角度、就绪或锁相状态。

## 6. 证据等级

### 已确认

- D挡 `ENABLE/READY`条件下，轻踩踏板会建立正扭矩请求。
- 实际扭矩与请求同方向、同帧跟随，随后轴速和车速上升。
- 两次加速均达到约11～12 km/h，链路重复。
- 正扭矩建立伴随Pack放电电流增加和小幅电压下降。
- 本工况没有触及BMS电流能力或电驱功率边界。

### 强候选解释

- `BMS_packCurrent`正值代表放电、负值代表充电/回收；方向与加速、减速过程一致，但应由TM3-005回收采集继续确认。
- 请求与实际扭矩的绝对Nm缩放基本可用；其趋势和跟随关系证据强于绝对标定值。

### 未确认

- 前电驱是否参与本次加速及其扭矩分配，因为 `0x1D8`定义不可靠。
- 踏板到逆变器内部电流环、转矩环的真实控制延迟。
- 旋变实时位置角和角度有效性状态。
- 未知候选ID的具体语义；自动排名只作为后续交叉验证线索。

## 7. 对控制树的增量

```text
READY / DI_systemState=ENABLE
  ├─ 前置条件：D挡、制动释放、高压母线已建立
  └─ 加速踏板请求
      └─ DI_torqueCommand 正扭矩
          ├─ DI_torqueActual 跟随
          │   └─ DI_axleSpeed 上升
          │       └─ DI_vehicleSpeed 上升
          └─ 高压能量输出
              ├─ BMS_packCurrent 放电增加
              ├─ BMS_packVoltage 轻微下降
              └─ 实际需求低于BMS/电驱能力边界
```

## 8. 最小下一步验证

1. 使用TM3-005验证松踏板后 `负扭矩→负Pack电流→车速下降` 的回收闭环，并确认Pack电流符号。
2. 在其他来源DBC中重点核对 `0x1D8`字段重叠和 `0x132`的6字节实车格式，不在未验证前写入前电驱基线。
3. 后续更高采样率或调试页数据出现时，再测量踏板、扭矩决策、电流环和机械响应的细粒度延迟。
4. 继续搜索行驶阶段的旋变/内部角度多路复用页；本次不因旋变告警为0而判定位置角链路已验证。
