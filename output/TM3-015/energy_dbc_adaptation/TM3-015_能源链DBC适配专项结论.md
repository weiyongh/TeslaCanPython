# TM3-015 能源链DBC适配专项结论

## 专项结论

本轮只核查能源测量链，不改变TM3-015既有充电时序基线。

| 核查项 | 专项评级 | 结论 |
| --- | --- | --- |
| `0x29D / CP_evseOutputDcCurrent` | **定量语义未验证** | 建立、稳定和归零时序可信；按当前factor得到128.108 A与Pack侧、累计能量和SOC数量级不闭合。问题最可能位于`0x29D`电流字段的factor或版本语义，而不是DLC补齐本身。 |
| `0x132 / BMS_packCurrent` | **可信（本实验定量Pack侧）** | 稳定段平滑电流193.880 A与同帧独立未滤波电流193.782 A高度一致；电压×电流约70.7 kW，并与累计充电量积分约70.65 kW闭合。原始符号按当前车型既有实验为负值充电，正文继续转换为“充入Pack为正”。 |
| `BMS_chgPowerAvailable` | **部分可信，P1能力候选** | ONYX的bit 38定义不适配；`Model3CAN.dbc`的bit 40、11位、0.125 kW定义得到稳定约72.98 kW，非充电阶段正确落在raw 2047=SNA，并略高于Pack实际约70.75 kW。当前可解释为“BMS计算的可用充电功率/能力上限候选”，不能解释为Request或Actual。 |
| TM3-015完整能源链 | **尚不能升级为完整定量基线** | Pack侧定量链已获得较强支持；CP/桩侧电流仍没有外部标定，因此不能形成桩端Actual→Pack Actual的完整定量链，也不能计算效率。 |

## 1. `0x29D`原始bit与DLC核查

- ASC中`0x29D`共2997帧，实际DLC恒为5；ONYX和`Model3CAN.dbc`均声明DLC 4。
- 已用字段范围：Current为bit 0–14，Voltage为bit 16–28，Stale为bit 29；均完全位于前4字节。ASC新增第5字节在2997帧中恒为`0x00`。
- 因此，**DLC 4→5的差异本身不会改变当前电流和电压字段的原始bit**，不能仅靠把DBC消息长度改成5解决128 A问题。
- 稳定段典型原始帧：`D5 06 79 13 00`。Current raw为`0x06D5=1749`，按当前15位有符号、factor 0.0732467得到128.108 A；该raw在整个稳定窗口595个采样中恒定。
- 15/16位和signed/unsigned在本窗口不会产生差异：raw为正且bit 15为0。Voltage从bit 16、13位按0.0732422解得约365.4 V，与Pack电压约364.9 V一致，说明`0x29D`并非整帧错位。
- 若仅调整factor使CP电流匹配Pack平滑电流，需要约`0.110852 A/bit`；当前项目中没有找到该factor的独立DBC来源。0.1会得到174.9 A，0.125会得到218.6 A，均不能与Pack侧精确闭合。

结论：`0x29D`电压字段定量较可信；电流字段的开始位、正负号和位宽在本窗口没有证据显示错误，**最可疑的是factor或该字段在当前车辆/软件版本下的真实语义**。不得用推算factor直接修补DBC。

## 2. `0x132` Pack电流核查

ASC中`0x132`共29973帧，实际DLC恒为6；相关DBC声明DLC 8。但本轮所需字段均被6字节完整覆盖：

- Pack Voltage：bit 0–15；
- Smooth Pack Current：bit 16开始；
- Unfiltered Pack Current：bit 32–47。

稳定段结果：

| 字段/定义 | 稳定段结果（充入Pack为正） | 说明 |
| --- | ---: | --- |
| ONYX `BMS_packCurrent`，bit16、15位、factor −0.1 | 193.880 A | 原始DBC值约−193.880 A |
| JSON `BMS_packCurrent`，bit16、16位、factor +0.1 | 193.880 A | 本窗口最高位为0，15/16位不影响量级；JSON采用相反符号约定 |
| Model3CAN `SmoothBattCurrent132`，bit16、16位、factor −0.1 | 193.880 A | 与ONYX量级一致 |
| Model3CAN `RawBattCurrent132`，bit32、16位、factor −0.05、offset 822 | 193.782 A | 同一原始帧中的独立电流字段，差约0.10 A |

Pack电压均值364.901 V，对应：

- 平滑Pack功率：70.747 kW；
- 未滤波Pack功率：70.711 kW。

同一帧两套不同位段、不同factor/offset的电流字段能够收敛，是本轮确认Pack电流量级的核心证据。符号方面，TM3-004正加速、TM3-005回收和TM3-006静态基线已经在当前车型采集域确认：当前ONYX约定正值放电、负值充电/回收。因此TM3-015正文采用“充入Pack为正”的人读转换是可信的；底层原始负号继续保留。

## 3. 46.8 kW与70.8 kW差异来源

差异最可能来自`0x29D / CP_evseOutputDcCurrent`一侧，而不是`0x132`Pack侧，依据如下：

1. Pack平滑电流和独立未滤波电流相差约0.10 A，对应功率均约70.7 kW。
2. `TotalChargeKWh3D2`候选计数在59.003 s内增加1.158 kWh，折算70.655 kW，与Pack V×I一致。该计数仍是社区DBC候选，但位段独立。
3. UI SOC在59.5 s内由28.2%升至30.5%。若仅用用户提供的55 kWh标称容量作数量级旁证，折算约76.5 kW；由于UI SOC量化、缓冲、容量口径及估算滤波未知，不能作为精密标定，但明显更接近70.8 kW而非46.8 kW。
4. `BMS_chgPowerAvailable`采用bit 40定义时约72.98 kW，也与Pack实际约70.75 kW形成合理的“能力略高于实际”关系。
5. 若CP侧实际只有46.8 kW，却有约70.7 kW持续进入Pack，将违反同一DC链路的能量守恒；约24 kW差异不能由一般辅助负载、滤波或采样错位解释。

这些证据足以否定当前128.108 A作为可信桩端实际电流，但尚不足以确定其正确factor或字段真实含义。

## 4. `BMS_chgPowerAvailable`位段与语义

定义冲突：

- ONYX/`tesla_model3.dbc`：start bit 38、11位、factor 0.125；稳定段35.946 kW。
- `Model3CAN.dbc`：start bit 40、11位、factor 0.125；稳定段72.976 kW。

bit 40定义具有更强适配证据：

- 非充电阶段raw为2047，准确命中DBC枚举`SNA`；
- 充电爬升段约69.4→72.8 kW，稳定段72.875–73.000 kW；
- 实际Pack功率约70.7 kW，未超过该能力候选。

bit 38定义会把相邻状态位并入11位数值，非充电阶段得到raw 2046而非SNA，并在稳定段错误地产生约35.9 kW。因此35.9 kW不应继续作为本车有效数值。

当前可接受中文语义：**“BMS计算的当前可用充电功率/充电能力上限候选（待跨SOC和桩功率验证），不是充电请求，也不是实际充电功率。”**证据等级建议维持P1、实验级中高置信度，不进入`Available→Actual`已确认控制关系。

## 5. 是否升级及最小下一步证据

- **Pack侧可以保存为TM3-015实验级定量基线**：约364.90 V、193.88 A（充入为正）、70.75 kW，适用窗口173.73–233.23 s。
- **完整能源链不能升级为定量基线**：桩/CP侧实际电流尚未独立标定，不能计算桩到Pack效率。
- 当前目录未发现与本次ASC可同步关联的桩屏照片、订单电压/电流/功率或外部电流测量记录。

最小补充证据优先级：

1. 优先查找本次充电订单或桩端记录，至少包含时间段、输出电量、持续时间；若能提供稳定段电压、电流、功率更佳。无需重新采集车辆数据即可先做平均功率核对。
2. 若必须补采，只需约60 s稳定直流快充窗口，同步拍摄/录制桩屏电压、电流、功率，并保留开始/结束统一时间标记；同时采集`0x29D`、`0x132`、`0x212`和累计充电量计数。
3. 在外部桩端电流确认前，不修改`0x29D`factor，不用Pack电流反推并写回所谓“正确factor”。

本专项没有改变“充电成功、建立与停止时序”的既有判断，也没有进入热管理或车辆故障诊断。
