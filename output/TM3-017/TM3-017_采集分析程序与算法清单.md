# TM3-017 采集分析程序与算法清单

**Experiment：** `TM3-017`

**Primary Round：** `S0030`

**Cross-Round Evidence：** `S0009`

**用途：** 记录本轮从采集包接入、Recognition、匿名raw报文分析、候选去伪、跨Round复核到控制结构判断实际使用的程序、运行环境与算法。

**信息边界：** `STRICT_NO_DBC_RAW_PAYLOAD_ONLY`

**重要声明：** 本轮报文分析没有使用DBC、DBC镜像、既有Signal解析答案、历史Signal答案、`cantools`或项目DBC解码器。ASC只被解析为`timestamp + CAN ID + DLC + payload bytes`；所有CAN ID和byte位置保持匿名raw身份。

## 3. 报文解析与判断算法

### 3.1 ASC原始行解析

使用正则表达式识别Vector ASC中的接收数据帧：

```text
timestamp  channel  CAN_ID  Rx  d  DLC  byte0 byte1 ...
```

解析结果为：

```text
(timestamp_s, can_id_integer, payload_bytes[0:DLC])
```

算法特征：

- CAN ID按十六进制转整数。
- payload按两个十六进制字符转byte，并严格截取到DLC。
- byte offset从0开始。
- 不解析bit field，不尝试字节序、符号、factor、offset或unit。
- 不合并同名Signal，因为本轮不存在Signal层。
- 非匹配行直接忽略；若没有任何数据帧则停止。

### 3.2 实际Clock与ASC相对时间映射

Acquisition Context使用以下信息建立时间边界：

1. VoiceRunner的`start_clock_epoch_ms`和Event的`session_script_time_us`。
2. `event_timeline.csv`已计算的`clock_iso`/`clock_epoch_ms`。
3. 照片自身`captured_clock`与`captured_script_time_us`。
4. ASC头部绝对日期/时间与帧相对秒数。

VoiceRunner换算关系为：

```text
event_clock_epoch_ms
  = session.start_clock_epoch_ms
  + round(session_script_time_us / 1000)
```

本轮窗口不是直接使用脚本计划时间。程序根据已审核照片的实际时间和Event实际提示Clock形成边界，并主动排除动作边沿：

| 窗口 | ASC时间 | 用途 |
| --- | ---: | --- |
| W1 | 5.000–75.000 s | 初始高设置稳定窗口 |
| W2 | 90.763–208.268 s | 低设置稳定窗口；从E03-P01实际照片确认点开始 |
| W3 | 227.478–330.000 s | 恢复高设置稳定窗口；从E06-P02确认点开始并排除E06-P01的21 A中间态 |

Event提示锚点为E03 78.322 s和E06 208.268 s。它们是VoiceRunner滴声时间，不是人工触控完成时间，因此只用于“提示后变化范围”，不能产生精确控制延迟。

### 3.3 三稳定窗口统计

对每个`(CAN ID, DLC, byte offset)`，分别收集W1/W2/W3内所有raw byte值，并计算：

- 中位数（median）：稳态中心值，降低短时尖峰影响。
- 众数（mode）：最常出现的离散raw值。
- 众数占比（mode fraction）：评估离散稳定程度。
- 极差（range）：`max - min`，观察窗口内离散或循环范围。
- 样本数门：每个窗口至少10个样本。

中位数选择不代表该byte是物理量。它只是对匿名离散raw序列的稳健位置统计。

### 3.4 “高—低—高”可逆候选规则

定义：

```text
down = median(W1) - median(W2)
up = median(W3) - median(W2)
return_error = abs(median(W3) - median(W1))
```

候选必须同时满足：

```text
down >= 2
up >= 2
return_error <= max(2, 0.15 * max(down, up))
```

这一步得到48个`HIGH_LOW_HIGH_RAW_BYTE`候选。算法只回答“该byte是否随三个窗口呈可逆层级”，不回答它代表什么，也不把48个byte等同于48个Signal。

### 3.5 变化点与边沿轨迹

对少数代表候选保存边沿区间内每次raw值变化：

- 调低边沿：75–90 s附近。
- 恢复边沿：205–230 s附近。

连续相同值只保留首次出现点；值改变时记录`asc_time_s`和`raw_value`。该轨迹用于观察阶梯、渐变、跳变和恢复形状。

### 3.6 t10 / t50 / t90首次越阈时间

针对P1/P2候选，以窗口中位数为起点和终点，定义分数阈值：

```text
threshold(f) = origin + f * (target - origin)
f ∈ {0.1, 0.5, 0.9}
```

在Event提示之后搜索第一次跨越阈值的帧，并计算相对提示的`t10`、`t50`、`t90`。下降和上升方向分别处理。

用途：比较候选是早期、中间还是较晚完成主要变化。

边界：结果相对VoiceRunner提示，而非相对人工触控完成，因此不能写成真实控制器响应延迟。

### 3.7 计数器/循环候选检测

在W2稳定窗口内，对候选连续非相同值计算模256差分：

```text
delta_i = (value[i+1] - value[i]) mod 256
```

若：

- 窗口内至少出现8个不同raw值；并且
- 最常见非零模差占全部非零变化的比例不低于0.90；

则标记为明确计数器或循环候选并淘汰byte单点解释。本轮检出12个此类候选。

该算法能发现固定步进，但不能覆盖所有伪候选；非固定步进周期、复用页和多状态payload还需完整payload复核。

### 3.8 复用页、交替payload和周期模式去伪

去伪分两类：

1. 程序化检测到的固定步进计数器/循环。
2. 经完整payload行为复核后显式固化的集合：
   - `invariant_mux`：完整payload在三个窗口相同、但因两页交替及样本奇偶导致byte中位数翻转。
   - `cyclic_or_multipage`：窗口内持续多页/周期切换或宽范围循环，单byte中位数不能代表阶跃。

因此这一阶段不是完全无监督算法。部分复用/周期集合是先观察完整payload模式，再在程序中固定，确保复现同一审核结论。

被淘汰的是“该byte作为本轮单点候选”的解释，不是整个CAN ID无信息。

### 3.9 100 ms零阶保持重采样

不同CAN ID的发送时间并不完全同步。为比较轨迹，程序在ASC 70–235 s建立100 ms时间网格，对每个候选使用最近一次已出现值进行保持：

```text
grid_value(t) = latest raw value whose timestamp <= t
```

这属于零阶保持（zero-order hold / held-last-value），使不同发送周期的序列能在同一时间坐标上比较。

它不会创建新的物理样本，只是为轨迹相关计算提供统一网格。

### 3.10 Pearson轨迹相关

对100 ms保持后的两个候选序列计算Pearson相关系数：

```text
r = Σ((x-x̄)(y-ȳ)) /
    sqrt(Σ(x-x̄)^2 * Σ(y-ȳ)^2)
```

仅保留`r >= 0.985`的候选对，并区分：

- `SAME_CAN_ID_ADJACENT`：同一CAN ID且byte相邻。
- `SYNCHRONOUS_TRAJECTORY`：其他高度同步轨迹。

相关性只用于发现同步行为和字段边界问题。它不证明同源、复制、派生、因果、相同物理量或相同Signal。

### 3.11 XOR变化掩码

对W1/W2及W2/W3中位raw值计算：

```text
fall_mask = median(W1) XOR median(W2)
rise_mask = median(W2) XOR median(W3)
```

用途是显示两次相反阶跃涉及哪些bit位置发生差异，并检查下降/恢复是否具有相似bit变化范围。

边界：这是byte级差异掩码，不是bit field识别；不能由此确定起始bit、位宽、符号或编码。

### 3.12 候选优先级与行为分组

最终P1/P2/P3/X不是一个通用自动评分公式：

- 自动统计提供稳定性、极差、众数占比、回归误差、计数器比例、边沿时序和相关关系。
- 明确计数器、交替payload及周期候选进入`X`。
- P1/P2/P3成员集合由上述统计、完整payload观察、相邻byte边界和两侧边沿形态综合复核后，在脚本中显式列出。
- 分组G-A至G-X同样是行为审核分类，不是机器学习聚类。

各级含义：

| 级别 | 含义 | 不代表 |
| --- | --- | --- |
| P1 | 三窗口稳定、可逆、边沿清楚，具有较高后续raw研究价值 | 物理重要度或Signal已确认 |
| P2 | 可逆关系存在，但字段边界、占空/脉冲或动态不对称仍待区分 | 次要物理Signal |
| P3 | 变化较弱、存在额外层级或恢复偏差 | 已否定整个CAN ID |
| X | 当前byte单点解释被计数、周期、复用或弱关系去伪 | 报文无用 |

实际结果为P1=5、P2=9、P3=4、X=30。

### 3.13 跨Round多状态窗口复核

跨Round程序先强制检查S0009 Acquisition Context为`APPROVED`，再只导入S0030的P1/P2候选。S0009两段ASC使用统一相对时间轴：

```text
第一段offset = 0.000 s
第二段offset = 443.000 s
保留442.372–443.000 s文件间隙
```

对六类已审核现场状态窗口计算每个候选的median/min/max，并在照片时间点±0.5 s内找最近raw样本：

- 未充电；
- 已连接未充电；
- 充电高位；
- 停止后仍连接；
- 解锁后仍连接；
- 拔枪后。

该算法用于：

- 查找S0030高/低之外的第三、第四raw层级；
- 否定相邻byte“简单副本”或固定比例解释；
- 检查早期、中间、较晚动态类别能否跨Round复现；
- 观察某报文是否只在特定状态发送。

跨Round排序`P1-A/P1-B/P1-C/P2/P2-`由复核结论在程序字典中显式固化，不是自动语义分类。

### 3.14 控制结构推理与Tree Gate

Control Structure Layer Review及Formal Control Tree Delta Gate没有由Python自动生成控制语义。它们使用以下证据推理规则：

1. 相反输入32→16→32与实际响应32→16→32、功率7→4→7 kW提供方向一致和可逆性。
2. W1/W2/W3均超过30秒，支持短时稳定结果。
3. E06-P01中设置已为32 A、实际仍为21 A，证明“设置接受”和“实际响应”不能合并为同一瞬时Node。
4. 内部路径没有直接Evidence，因此必须保留未观测区域。
5. raw早/中/晚簇只支持行为类别与先后关联；串行、共同潜变量并行和混合结构仍不可区分。
6. 只有已审核、可追溯且没有竞争解释足以推翻的外部Node、系统级Relationship和Condition进入Tree Gate。

该层属于受Evidence约束的分析判断，不是报文自动命名算法，也不产生Signal映射。

## 7. 算法适用范围与复用注意事项

1. 三窗口阈值、Event时间及ASC路径是TM3-017/S0030专项常量，不是可直接套用其他Round的通用配置。
2. HIGH-LOW-HIGH规则适合本轮相反阶跃设计；单向动作、脉冲动作或状态机切换需要不同候选规则。
3. P1/P2/P3集合、周期/复用集合及跨Round排序包含审核后显式固化判断，不应当作对新数据自动泛化的模型。
4. Pearson相关适合发现同步轨迹，但强相关不能决定控制方向、同源关系或Signal身份。
5. byte单点分析是发现候选的入口，不足以确定相邻byte是否组成字段；本轮已明确保留多个字段边界未决项。
6. 历史Round只能作为保持原始匿名身份的独立行为复核，不能向新Round迁移Signal语义。
7. 正式控制树准入依赖人工审核后的Evidence强度和竞争解释审查，不能仅由统计分数自动写树。

## 8. 结论

TM3-017实际使用的CAN报文算法是一条透明、可复现的盲态raw行为链：

```text
ASC文本解析
→ 实际Clock约束的稳定窗口
→ byte级稳健统计
→ 相反阶跃可逆筛选
→ 计数/周期/复用去伪
→ 边沿与同步轨迹比较
→ 相邻byte/字段边界复核
→ S0009跨状态反证
→ Evidence约束下的控制结构判断
```

它能够判断匿名raw位置是否具有稳定、可逆、早/中/晚动态或跨状态行为价值，但不能独立完成Signal语义、bit field、scale、unit、ECU或内部控制角色识别。本轮正式结论正是按这一能力边界形成。
