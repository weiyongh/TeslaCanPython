# TM3-005 低速松电门回收分析结论

## 1. 诊断问题与适用范围

诊断问题：车辆在D挡和 `READY/DI_systemState=ENABLE` 状态下，以约15 km/h行驶并完全松开加速踏板后，负扭矩请求、实际负扭矩、轴速/车速、电驱功率和动力电池电流如何变化，两个回收段是否重复。

适用范围：本结论仅适用于 `input/can_20260827140713_TM3-005_低速松电门回收采集.asc`、当前车辆状态和 `input/tesla_model3_ONYX.dbc`。道路坡度、回收设置及电池温度缺少独立现场记录，因此本次建立控制链和方向基线，不把减速度或峰值回收能力推广到其他环境。

## 2. 实际动作与脚本偏差

ASC总时长约130 s，共368,770帧。两次有效自然回收均未踩制动，直到车速降至约8 km/h后才踩制动完成停车。

| 阶段 | 第一次 | 第二次 |
|---|---:|---:|
| D挡/ENABLE | 20.034/20.043 s | 最终79.550/79.559 s |
| 完全松开加速踏板 | 39.8138 s | 94.5498 s |
| 松电门起始车速 | 15.68 km/h | 15.92 km/h |
| 踩制动结束自然回收 | 49.6814 s | 104.3554 s |
| 踩制动时车速 | 8.24 km/h | 8.08 km/h |
| 回P | 60.1114 s | 114.8370 s |

第二次准备阶段存在明显操作偏差：75.450 s挂D，77.510 s回P，79.550 s再次挂D，随后才进入有效加速和回收段。该偏差不影响94.55～104.36 s的第二次自然回收，但不能把75～80 s作为单一连续D挡准备窗口。

## 3. 两次回收关键时序

| 观察量 | 第一次回收 | 第二次回收 |
|---|---:|---:|
| 踏板开始明显下降 | 39.7337 s | 不晚于94.2098 s |
| 踏板完全为0 | 39.8138 s | 94.5498 s |
| 扭矩请求首次转负 | 39.9833 s，-60 Nm | 94.4797 s，-14 Nm |
| 实际扭矩首次转负 | 39.9833 s，-40 Nm | 94.4797 s，-14 Nm |
| 电驱功率首次转负 | 40.0827 s，-0.5 kW | 94.6306 s，-0.5 kW |
| Pack电流首次转负 | 40.0845 s，-0.4 A | 94.6454 s，-1.6 A |
| 最小请求扭矩 | -280 Nm | -288 Nm |
| 最小实际扭矩 | -292 Nm | -312 Nm |
| 最小电驱功率 | -3.5 kW | -4.0 kW |
| 最小Pack电流 | -9.2 A | -9.5 A |

第一次从踏板完全为0到负扭矩首次可见约169.5 ms；第二次在踏板仍约1.6%时扭矩已经转负，比完全为0早约70 ms。这说明回收不是简单的“踏板数值必须等于0才开启”，而是随着踏板释放进入零扭矩交点后开始形成负扭矩。踏板到扭矩的精确内部延迟仍受 `0x108`约100 ms采样周期限制。

负扭矩区间内，请求与实际扭矩平均绝对差约2.43 Nm和1.43 Nm；除了回收建立初期的瞬态差异，跟随关系良好。

### 额外说明：非零踏板与下坡回收

以下内容是控制原理补充，不是TM3-005脚本直接验证的实验结论：车辆在下坡时，即使加速踏板没有完全松开，也可能产生能量回收。加速踏板表达的是驾驶员的运动/扭矩意图，不是“只要踏板大于0，电机就必须输出正扭矩”的开关。

同一踏板位置在不同外部负载下可能对应不同扭矩方向：

```text
相同的较浅踏板开度
  ├─ 平路：克服行驶阻力，可能需要轻微正扭矩
  ├─ 缓下坡：重力与行驶阻力接近平衡，扭矩可能接近0
  └─ 较陡下坡：重力推动汽车继续加速
          └─ 为维持驾驶员期望速度，目标扭矩可能转负并发生回收
```

因此，零扭矩交点不是固定踏板百分比，而会随车速、车辆加速度趋势、坡度/外部负载、驾驶模式、BMS接收能力、电驱回收能力和稳定控制条件移动。诊断回收是否发生，应以扭矩和能量流为核心，而不能只检查踏板是否等于0：

```text
DI_torqueCommand < 0       回收请求已经生成
DI_torqueActual < 0        电驱已经执行负扭矩
DI_elecPower < 0           电驱处于发电方向
BMS_packCurrent < 0        能量实际进入动力电池
```

以后若设计下坡专项实验，应保持非零踏板并记录坡度、车速和纵向加速度，验证零扭矩交点如何随坡度移动；在完成该实验前，不把下坡回收的踏板阈值或减速度写入本车正常基线。

## 4. 请求—条件—决策—执行—反馈—结果

### 请求

驾驶员逐步释放 `DI_accelPedalPos`，由约7.6～8.4%下降至0。车辆没有在有效回收段踩制动。

### 条件

- `DI_gear=D`且 `DI_systemState=ENABLE`，即当前车型CAN层面的READY/可驱动状态。
- 高压接触器已闭合，DC-link已经建立。
- `BMS_maxChargeCurrent=250 A`全程保持，回收接收能力边界没有收紧。
- 回收开始车速约15.7～15.9 km/h。

### 决策与执行

踏板经过零扭矩交点后，`DI_torqueCommand`由正转负；`DI_torqueActual`同步转负并跟随。负扭矩峰值建立后随车速降低逐渐减小，`DI_axleSpeed`和车速连续下降。

### 电池与高压反馈

- `DI_elecPower`由正转负，最低约-3.5/-4.0 kW。
- `BMS_packCurrent`由正放电转为负值，最低约-9.2/-9.5 A。
- `BMS_packVoltage`由负载阶段最低约347.35～347.37 V，在回收阶段最高升至约348.69～348.75 V。
- `HVP_dcLinkVoltage`回收阶段最高约348.9 V，与能量由电驱侧返回高压母线的方向一致。

以上结果与TM3-004正加速形成相反且自洽的能量方向，现可确认当前DBC/采集域内：`BMS_packCurrent>0`表示电池放电，`BMS_packCurrent<0`表示电池充电/回收。

### 最大驱动与回收能力边界

本次已经解析到的实际功率和能力边界如下：

| CAN ID | Signal | 中文含义 | TM3-005结果 | 使用边界 |
|---:|---|---|---:|---|
| `0x266` | `DI_elecPower` | 电驱当前实际电功率 | 最低约-4.0 kW | 正值为驱动用电，负值为回收发电；方向已由TM3-004/005交叉确认 |
| `0x268` | `DI_sysDrivePowerMax` | 电驱系统当前最大允许驱动功率 | 248 kW，全程不变 | DBC解释值；绝对标定和是否为车轴侧/系统侧边界仍需跨车型软件验证 |
| `0x268` | `DI_sysRegenPowerMax` | 电驱系统当前最大允许回收功率 | 92 kW，全程不变 | DBC定义带偏移，绝对值需继续验证；本次角色可解释为系统回收功率上限 |
| `0x2D2` | `BMS_maxDischargeCurrent` | 电池最大允许放电电流 | 682.624 A，全程不变 | 电池放电能力边界，不是实际放电电流 |
| `0x2D2` | `BMS_maxChargeCurrent` | 电池最大允许充电/回收电流 | 250 A，全程不变 | 电池回收接收能力边界，不是实际回收电流 |
| `0x132` | `BMS_packCurrent` | 电池实际电流 | 最低约-9.5 A | 本次实际回收电流，远未达到允许边界 |

主用DBC中还定义了以下BMS功率边界，但本次没有成功得到可靠数值：

| Signal | 中文含义 | 本次状态 |
|---|---|---|
| `BMS_maxDischargePower` | BMS最大允许放电功率 | DBC有定义，本次未可靠解码，不写入数值 |
| `BMS_maxRegenPower` | BMS最大允许回收功率 | DBC有定义，本次未可靠解码，不写入数值 |

控制边界关系应理解为：

```text
BMS电池充/放电能力
  + 电驱硬件与温度能力
  + 车速、稳定控制和整车策略
        ↓ 取当前最严格限制
DI_sysDrivePowerMax / DI_sysRegenPowerMax
        ↓
实际DI_elecPower必须处于允许范围内
```

本次实际回收功率约4 kW、实际回收电流约9.5 A，均远低于对应的DBC解释边界，因此只能建立“轻度回收正常闭环”，不能用本次数据验证92 kW最大回收能力是否真实可达。

### 结果

```text
D挡 + ENABLE(READY) + 车辆行驶
  → 释放加速踏板并越过零扭矩点
  → DI_torqueCommand转负
  → DI_torqueActual负向跟随
  → DI_elecPower转负
  → BMS_packCurrent转负
  → Pack/DC-link电压轻微抬升
  → 轴速和车速下降
```

两次自然回收约10 s内分别由15.68降至8.24 km/h、15.92降至8.08 km/h，对应平均减速度约0.21和0.22 m/s²。该数值受坡度、轮胎和车辆回收设置影响，只作为本次实验描述，不作为通用正常阈值。

## 5. 制动与自然回收的边界

- 第一次49.681 s、第二次104.355 s才踩下制动，此前链路属于可确认的松电门自然回收。
- 踩制动时车辆仍约8 km/h，因此本次没有验证“只靠松电门回收到完全停车”。
- 踩制动后的负扭矩可能包含电制动与液压制动协调，不纳入本实验的纯松电门基线。
- `DI_regenLight`全程解码为0，与已经确认的负功率、负Pack电流矛盾，说明该字段可能是特定显示阈值、版本不匹配或定义不适用；不能用其判断是否发生回收。

## 6. 系统边界与DBC冲突

### 可可靠使用

- `0x118`：踏板、挡位、系统状态。
- `0x108`：后电驱请求扭矩、实际扭矩和轴速。
- `0x257`：电驱侧车速。
- `0x266`：电驱电功率及其方向。
- `0x132`：Pack电压、电流；继续采用允许6字节实车帧截断解码的版本差异处理。
- `0x2D2`：BMS最大允许充放电电流边界。

### 不可可靠使用

- `0x1D6 / DI_limits`实车报文与当前DBC定义不能成功解码，`DI_limitRegenPower`和 `DI_limitRegenTorque`不能用于判断本次是否限回收。
- `0x1D8 / DIS_torque`定义存在字段重叠和物理不合理结果；本车为单后电机，也不应把DIS自动解释成前电驱。
- 后电驱告警矩阵 `0x356/0x35A`在正常采集中未出现，无法直接确认旋变、缺相或功率级告警状态。
- 本次仍没有三相电流页32/38、旋变页48/52或实时角度。

## 7. 证据等级

### 已确认

- 两次松电门均触发负扭矩请求和实际负扭矩。
- 负扭矩伴随负电驱功率、负Pack电流及Pack/DC-link电压抬升。
- 轴速和车速随回收连续下降，两个回收段方向一致。
- 当前采集域内Pack电流正负号已经由TM3-004与TM3-005交叉确认。
- 本工况的回收电流远低于BMS最大允许充电电流，没有能力边界饱和证据。

### 强候选解释

- 回收开始点由踏板映射中的零扭矩交点决定，而非必须等待踏板值严格等于0；第二次事件时序直接支持这一点。
- 请求/实际扭矩的绝对Nm缩放具有物理一致性，但测量参考点仍应理解为DBC定义下的电驱/车轴等效扭矩。

### 未确认

- 液压制动介入后的电制动混合比例。
- 不同SOC、温度、坡度和回收设置下的减速度与峰值回收能力。
- 回收限值位、三相电流、旋变状态和后电驱告警的直接CAN状态。

## 8. 对控制树的增量

```text
READY + D挡 + 车辆行驶
  └─ 驾驶员意图与车辆运动状态
      ├─ 本次实测入口：加速踏板释放
      └─ 其他可能入口：下坡外力推动、车速保持等（非本次实测）
          ↓
      目标扭矩越过零扭矩点
          └─ 回收扭矩需求
              └─ 回收能力裁决
                  ├─ BMS电池接收能力
                  │   ├─ BMS_maxChargeCurrent = 250 A
                  │   ├─ BMS_maxRegenPower：本次不可见
                  │   └─ SOC、温度、电压等电池条件
                  ├─ 电驱回收能力
                  │   └─ DI_sysRegenPowerMax = 92 kW（DBC解释值）
                  ├─ 整车限制
                  │   ├─ 车速与踏板映射
                  │   ├─ 稳定控制/附着条件
                  │   └─ 故障、限扭及制动协调
                  └─ 生成允许的负扭矩请求
                      ├─ DI_torqueCommand < 0
                      ├─ DI_torqueActual 负向跟随
                      │   └─ 轴速/车速下降
                      └─ 能量回流
                          ├─ DI_elecPower最低约-4.0 kW
                          ├─ BMS_packCurrent最低约-9.5 A
                          └─ Pack/DC-link电压轻微抬升

边界比较
  ├─ 实际回收功率约4 kW << DI系统回收上限约92 kW
  ├─ 实际回收电流约9.5 A << BMS允许充电电流250 A
  └─ 本次未触及回收能力上限
```

对应的诊断断点为：

```text
回收偏弱或没有回收
  ├─ 踏板意图与车辆运动状态是否要求负扭矩？
  ├─ BMS是否允许充电/回收？
  ├─ DI_sysRegenPowerMax是否被压低？
  ├─ DI_torqueCommand是否产生负值？
  ├─ DI_torqueActual是否跟随负请求？
  ├─ DI_elecPower和BMS_packCurrent是否转负？
  └─ 是否存在稳定控制、故障或制动协调限制？
```

## 9. 最小下一步验证

1. 后续在不同SOC和温度下重复相同初速，建立回收扭矩、电流与减速度的条件化范围。
2. 单独设计“松电门自然回收”和“踩制动混合回收”的同初速对照，分离踏板回收与液压制动协调。
3. 维护模式采集重点检查 `0x7D5`页32/38、48/52及后电驱告警矩阵是否出现。
4. 如获得真实无法驱动、旋变或缺相故障样本，优先比较 `torqueCommand→torqueActual→axleSpeed→PackCurrent`在哪一级断链。
