```plain text
                                Driver
                                  │
                                  ▼
                                 VCU
                                  │
         ┌───────────────┬────────┼───────────┬───────────────┐
         │               │        │           │               │
         ▼               ▼        ▼           ▼               ▼
       BMS             MCU      OBC/DC       HVAC         ABS / EPS / BCM
  (电池管理系统)   (电驱控制)   Charging    热管理控制      底盘/车身相关
         │               │        │           │               │
         │               │        │           │               │
```

---
## 1、总架构图的核心概念 
这张图其实表达了整车最重要的五层关系：
```plain text
Driver
↓
整车控制（VCU）
↓
各子系统控制器
↓
能源与执行系统
↓
车辆运动 / 热管理 / 充电 / 供电
```
也就是说：
```plain text
人发出意图
→ VCU统筹
→ 各子系统控制器执行
→ 电池提供能量
→ 各系统完成功能
```
---
## 2、总架构图的作用和意义 
这张图属于：
```plain text
① 整车架构图
```
它解决的是：
- 整车有哪些系统
- 谁和谁发生关系
- 哪些是控制层
- 哪些是执行层
- 哪些是能源层
它不是控制树，也不是故障树，但它是后面一切分析的**总入口**。
---
## 3、总架构图的四大块构成    
这张图可以理解成四大块。
---
### 1 ）控制中心
```plain text
VCU
```
作用：
- 接收驾驶员意图
- 协调整车扭矩
- 协调能源分配
- 统筹子系统协同
- 参与安全许可
这是整车控制层的中心。
---
### 2 ）能源中心
```plain text
HV Battery System
```
包括：
- 动力电池
- BMS
- 高压配电
- 高压供能
作用：
- 提供高压能源
- 决定是否允许放电/充电
- 决定最大可用功率
这是整车能源层的核心。
---
### 3 ）功能子系统
主要包括：
```plain text
电驱系统
充电系统
热管理系统
低压供电系统
底盘/车身系统
```
它们各自完成整车不同功能。
例如：
- 电驱系统负责把电能变成驱动力
- 充电系统负责把外部能量引入整车
- 热管理系统负责温度控制
- DC-DC负责给12V系统供能
- ABS/EPS/BCM负责底盘与车身功能
---
### 4 ）执行结果
最终落到：
```plain text
车辆运动
温度变化
电池充放电
低压供电
```
也就是真正能观察到的现象层。
---
## 4、总架构图如何对应“四条链路”
这张总架构图虽然没有把四条链用四种颜色画出来，但它其实已经把四条链都包含了。
---
### 1 ）动力链
```plain text
VCU → MCU → Electric Drive → Motor → Reducer → Wheel
```
这是：
```plain text
电能转成车辆运动
```
---
### 2 ）能源链
```plain text
HV Battery System → Electric Drive / HVAC / OBC / DC-DC
```
这是：
```plain text
高压能源向各系统分配
```
还有：
```plain text
HV Battery → DC-DC → 12V Battery → LV systems
```
这是低压能源链。
---
### 3 ）控制链
```plain text
Driver → VCU → 各子系统控制器
```
例如：
- VCU → MCU
- VCU → BMS
- VCU → OBC
- VCU → HVAC
- VCU → ABS/EPS/BCM
这是信息与指令链。
---
### 4 ）安全主线
安全不一定像其他链那样独立成一条物理主线。
在这张总图里，安全更适合被理解为：
```plain text
嵌入在VCU、BMS以及各子系统控制器中的约束逻辑
```
例如：
- BMS保护
- HVIL
- 绝缘监测
- Drive Enable
- 制动/档位/碰撞条件
- 过温/过流/通信异常保护
所以在总图里，安全不是单独拉一根线，而是：
```plain text
控制层中的约束逻辑
```
---


### 2）例如拆电池系统

# 二、L3 学习图谱/步骤 
每个子系统的学习，都可以沿用如下学习和知识组织结构。         
---
## 1、通过总架构图找出子系统边界   
```plain text
整车系统总图
```
作用：
```plain text
找位置
看边界
看接口
```
---
## 2、子系统结构
作用：
```plain text
看主链
看部件
看边界
```
例如电驱系统：
```plain text
*Battery* → Inverter/MCU → Motor → Reducer → Wheel
```
---
## 3、系统边界 /跨系统控制流程
作用：
```plain text
看协同关系
看请求与仲裁
```
例如：
```plain text
Driver → VCU → BMS → MCU → Motor
```
---
## 4 、控制树
```plain text
XX控制

↓

请求

↓

条件检查

↓

执行

↓

反馈确认

↓

结束

-- or --

请求

↓

评估

↓

能力计算

↓

授权

↓

执行

↓

持续监控

↓

保护
```
作用：
```plain text
看子系统内部控制逻辑
```
例如：
```plain text
MCU
├ 扭矩控制
├ 电流控制
├ 速度控制
└ PWM控制
```
---
```plain text
XX控制

├─请求(Request)

├─条件检查(Check)

├─状态评估(Evaluation)

├─能力计算(Capability)

├─控制执行(Action)

├─反馈确认(Feedback)

└─持续监控(Monitor)
```
## 5、诊断树
作用：
```plain text
从现象逆推到节点
```
例如：
```plain text
READY但不走
├ VCU未发扭矩
├ BMS限制放电
├ MCU未执行
├ 电机故障
└ 机械侧故障
```
---
```plain text
一级：
功能（Function）

二级：
功能是否正常（Yes/No）

三级：
需要验证什么（Verification）

四级：
可能原因（Possible Cause）

五级：
下一步检查（Next Action）
```
## 6、状态机
 以后分析任何ECU，都可以套用这条主线，只是在不同控制器中，初始化和自检的具体内容有所不同。这种统一建模方式，会让后续分析整车系统时更加顺畅。
```plain text
Sleep
   ↓
Wake-up
   ↓
Boot（控制器启动）
   ↓
Initialization（软件初始化）
   ↓
Self Check（系统自检）
   ↓
Ready（进入正常运行）
```

# 五、新能源汽车系统建模方法
以分层方式对动态控制进行建模：
 
```javascript
状态（上层） 

控制（中层） 

能量（下层）
```
这一步其实非常关键。因为很多人学到后面会越来越乱。原因不是知识太多。而是没有组织结构。
现在这个建模 ：
```javascript
上层：状态
中层：控制
下层：能量
```
其实已经非常像：
一个稳定的系统分析模板，这个分层非常自然，因为新能源汽车本质上就是这样个控制系统    ：
```javascript
状态驱动

→ 控制协调
→ 能量执行
```
<empty-block/>
## 1、上层：状态层（State Layer）
这里回答系统现在发生了什么，这些都是状态量，例如：
```javascript
轮速
转速
Yaw Rate
转向角
SOC
温度
电流
电压
```
## 2、中层：控制层（Control Layer）
这里回答系统决定做什么，这里本质是决策与控制，例如：
```javascript
VCU协调
ESP限扭
ACC调速
MCU执行
FOC控制
PWM生成
```
## 3、下层：能量层（Energy Layer）
这里回答能量怎么流动，例如：
```javascript
驱动

Battery
→ Inverter
→ Motor
→ Wheel

回收
Wheel
→ Motor
→ Inverter(整流)
→ Battery
```
这三层刚好对应：看见世界（状态）—\>  做出决策（控制）—\>  改变世界（能量）<br>这样就可以形成一个 固定分析模式，这一点特别重要。因为以后无论：
```javascript
ESP
TCS
AEB
巡航
热管理
充电控制
```
都能套用 这个建模和分析方法 。
