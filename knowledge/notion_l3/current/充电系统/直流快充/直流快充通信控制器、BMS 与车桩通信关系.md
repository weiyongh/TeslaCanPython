# 直流快充通信控制器、BMS 与车桩通信关系

在分析新能源汽车直流快充控制架构时，需要首先区分不同的充电通信标准，不能把 **CCS / ISO 15118 的 PLC 通信方式**与**中国 GB/T 27930 / ChaoJi 的 CAN 通信方式**混为一谈。
## 1. 中国 GB/T / ChaoJi 体系
按照 GB/T 27930-2023，非车载充电机与电动汽车之间的数字通信主体定义为：
**充电机侧 SECC（Supply Equipment Communication Controller） ↔ 车辆侧 EVCC（Electric Vehicle Communication Controller）**
二者之间的数字通信基于 **CAN**。
因此，在 GB/T 27930-2023 / ChaoJi 体系下，不能描述成：
充电桩 → PLC → EVCC → CAN → BMS
更准确的逻辑关系是：
充电桩侧
**SECC**
↓
**车桩 CAN 通信**
↓
车辆侧
**EVCC**
↓
车辆内部控制网络 / 控制逻辑
↓
**BMS、VCU、充电接口控制相关 ECU 等**
其中，“EVCC”首先是一个**功能角色**，即车辆侧负责与充电设备通信的通信控制实体，并不意味着所有车型都必须存在一个名称就叫“EVCC”或“快充控制器”的独立 ECU。
GB/T 27930-2023 明确允许 EVCC 包括但不限于 BMS。因此在某些车辆架构中，BMS 可以直接承担车桩通信功能；在另一些车型中，也可以由独立充电控制器、充电接口控制器或其他 ECU 承担 EVCC 功能，再与 BMS、VCU 等通过车内网络交换信息。
因此，分析具体车型时必须进一步确认实际 ECU 拓扑，不能仅根据“EVCC”这个标准术语推断车辆一定存在独立快充控制器。
## 2. BMS 的核心职责
无论 EVCC 功能具体部署在哪个 ECU，BMS 都是动力电池充电安全与能力边界的重要决策者。
BMS主要负责：
- SOC、电芯电压和电池温度等状态估算；
- 电池故障与安全状态判断；
- 最大允许充电电压计算；
- 最大允许充电电流计算；
- 最大允许充电功率或充电能力边界计算；
- 根据充电过程持续更新电池允许的充电条件；
- 对过压、过温、过流等异常状态进行保护。
这些电池侧状态和能力信息最终参与车桩之间的充电协商和充电过程控制。
但不能简单表述为：
“BMS一定通过车内CAN把需求发送给独立EVCC，再由EVCC转换后发送给充电桩。”
这只是某些车型可能采用的一种实现架构，而不是 GB/T 27930 对所有车辆规定的固定架构。
## 3. VCU及其他车辆控制器
VCU以及充电接口相关控制器可能参与：
- 整车充电条件判断；
- P挡等车辆状态确认；
- 高压安全条件确认；
- 充电接口状态检测；
- 电子锁控制；
- 充电唤醒；
- 高压系统状态协调；
- 充电允许/禁止判断。
但是这些功能究竟由 VCU、BMS、充电接口控制器还是其他 ECU 承担，属于**具体车型控制架构**，不能由 GB/T 27930 直接推定。
同样，直流快充接触器由哪个 ECU 直接驱动，也应根据具体车型的电气架构、原理图和实车信号确定，不能笼统认定由 EVCC 直接控制。
## 4. CCS / ISO 15118 体系与国标体系的区别
PLC 通信主要应放在 CCS / ISO 15118 等体系中理解。
典型 CCS 通信链路可以抽象为：
充电桩侧 SECC
↓
**PLC通信**
↓
车辆侧 EVCC
↓
车辆内部通信网络
↓
BMS / VCU / 其他控制器
这里 EVCC 承担 ISO 15118 等车桩通信协议相关功能，因此“PLC通信控制器/协议网关”的描述比较合适。
但不能把这一架构直接套用到 GB/T 27930-2023 / ChaoJi。
## 5. 对L3诊断最重要的理解
从诊断角度，不应首先假定：
“快充控制器 = PLC网关 = BMS与充电桩之间唯一中间节点。”
更稳妥的控制链应抽象为：
**充电枪物理连接**
→ **控制导引/连接确认**
→ **车桩通信建立**
→ **车辆与充电机参数交换**
→ **BMS计算电池充电能力**
→ **整车安全条件判断**
→ **绝缘/高压安全检查**
→ **充电允许**
→ **高压充电回路建立**
→ **充电机输出**
→ **BMS持续更新允许电压/电流**
→ **充电过程控制**
→ **正常或故障结束**
然后再针对具体车型回答三个问题：
**谁负责车桩通信？谁做充电决策？谁实际执行接触器、电子锁和高压回路控制？**
这三个角色可能集中在一个 ECU，也可能分布在 BMS、VCU、充电接口控制器等多个 ECU 中。
因此在建立具体车型控制树时，应坚持：
**标准定义通信规则和功能角色，车型架构决定这些角色具体落在哪个 ECU 上。**
这是分析快充控制链时需要保留的关键边界。
