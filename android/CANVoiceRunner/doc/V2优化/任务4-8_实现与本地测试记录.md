## 3. 统一 Session 产物

```text
Download/CANVoiceRunner/
└── <脚本名>__<yyyyMMdd_HHmmss_SSS>__<S####>/
    ├── session.json
    ├── event_timeline.csv
    ├── photos/
    │   └── <event_id>-P<序号>_<事件名>_<拍摄时间戳>.jpg
    └── audio/
        └── <脚本名>_录音_<录音起始时间戳>.m4a
```

导出 ZIP 保留上述 Session 根目录。照片被外部删除时，导出前把对应 JSON `file_status` 更新为 `UNAVAILABLE`，保留 Photo 元数据，并跳过不存在的文件，避免整个 ZIP 导出失败。

## 4. 时间与状态实现核对

| 项目 | 实现规则 |
|---|---|
| Session 零点 | 最后一次准备倒计时结束、正式开始采集时建立 `elapsedRealtimeNanos()` 与 Clock 锚点 |
| `script_time` | 单调连续流淌；暂停只冻结脚本计划进度，不冻结此时间 |
| Event 触发 | 计划节点触发滴声时记录 `trigger_script_time_us`，状态自动成为 `triggered` |
| Event 跳过 | 只允许当前已触发 Event；保留触发时间并增加 `skip_script_time_us` |
| Photo 时间 | 使用图像 `ImageInfo.getTimestamp()`；与 Session 使用同一 BOOTTIME/REALTIME 单调时间域 |
| Note 时间 | 打开新增入口时冻结创建时间；修改和逻辑删除分别记录实际操作时间 |
| Audio 时间 | 记录请求时间；优先用 `AudioTimestamp.TIMEBASE_BOOTTIME` 反推首个有效帧，无法取得时显式记录 `TIMESTAMP_UNAVAILABLE` |
| Event CSV Clock | `start_clock_epoch_ms + round(session_script_time_us / 1000)` |
