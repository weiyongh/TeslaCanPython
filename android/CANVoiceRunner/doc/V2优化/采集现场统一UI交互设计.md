设计原则是沿用既有界面的主要结构和使用习惯，通过明确分区增加必要功能；以简单、够用、现场易操作为目标，不为美观进行无必要重构。

## 一、显示类

### 1. 顶部工具与 Clock

顶部保留并扩展为：

```text
[导入脚本] [查看脚本] [导出]
脚本文件名                       HH:mm:ss
```

- 当前 Clock 显示到秒。
- 开始和结束采集时分别记录完整的 `start_clock`、`end_clock`，包含日期、时区和毫秒。
- 采集中禁用“导入脚本”，防止运行脚本与界面脚本不一致。
- “导出”是否可用由是否存在可导出会话数据决定；采集中不执行会破坏当前会话的导出动作。

### 2. 既有采集执行区

中央区域沿用既有 App：

```text
脚本计划进度
当前 action
橙色倒计时/执行状态
下一操作及原始 plan_time
```

- 中央大字时间显示可暂停的脚本计划进度，反映当前已运行到原脚本 `plan_time` 时间窗口的何处。
- 暂停播报时，中央时间冻结在暂停时对应的 `plan_time` 时间点；恢复后继续推进。
- 橙色圆形区域保留现有倒计时与“执行”反馈。
- 当前动作始终来自脚本原始 `action`。
- 下一操作显示脚本原始 `plan_time`，暂停、跳过或延后均不得修改它。
- 稳定界面帧中，中央脚本计划进度必须小于下一操作的 `plan_time`。到达事件时点时，程序先触发并记录当前事件，再切换到后一事件，不让界面停留在“中央时间大于或等于下一操作时间”的状态。
- 实际事件触发的 `trigger_script_time_us` 不在主界面显示，只由程序记录和导出。

实现约束：既有采集执行区的 UI 布局与外观默认原样保留。为实现暂停、连续 `script_time`、计划播报续接和事件状态，内部程序逻辑及界面数据来源允许调整；逻辑变化不等于授权改变 UI。中央大字号计时、当前动作、橙色倒计时、下一操作的布局、尺寸、颜色、文字层级及其他可见表现不得因统一风格、美观或代码整理而改动。若功能确实要求任何可见 UI 变化，必须先提交具体变动并经人工审核。新增 Clock、证据摘要和操作分区优先布置在既有执行区外围。

真实连续流淌的 `script_time` 在顶部当前 Clock 后以“耗时”显示，例如 `15:30:25  耗时 04:04`。“耗时”可使用有区分度的彩色文字，但不放大、不与中央脚本计划进度争夺视觉优先级。

### 3. 证据摘要区

执行区下方预留一行：

```text
照片 2    备注 0    ● 录音中
```

- 照片显示当前 Session 成功保存的总数；`照片 N` 同时是任务 4 的照片列表入口，`照片 0` 置灰且不可点击。
- `备注 N` 显示当前 Session 未删除的事件备注总数，不包含照片备注；点击进入按 Event 分组的事件备注列表。
- 录音显示当前 Session 的只读状态：`录音关闭 / 录音已开启 / 录音准备中 / ● 录音中 / 本次未录音 / 录音失败 / 录音已保存 / 录音保存失败`。
- 本区只显示摘要，不在主界面展开照片、备注或录音管理。

### 4. 会话状态

操作区之间显示明确状态：

```text
播报运行中
播报暂停中 · script_time 继续
```

不得只显示“暂停中”，避免被理解为真实采集时间已经暂停。

## 二、操作类

### 1. 证据操作分区

第一排预留：

```text
[拍照] [备注] [录音：关/录音：开]
```

- “拍照”属于任务 4，一次操作关联点击时冻结的当前 Event，同一 Event 支持多张照片；采集中和播报暂停中可用，其他会话阶段置灰。
- “备注”属于任务 5，作用于点击时冻结的当前 Event；事件允许多条备注，照片备注从具体照片入口进入且一张照片同时最多一条有效备注。
- 录音复用第三个按钮位置，但它是采集前选项而非采集中的操作：默认显示“录音：关”，用户可在开始采集前切换为“录音：开”。
- 用户首次点击“录音：关”时检查麦克风权限：已授权则直接开启；可申请时触发 Android 系统权限框，授权成功后自动开启，拒绝则保持关闭；永久拒绝时提示前往系统应用设置。
- 权限申请发生在准备倒计时和 Session 之前，不启动录音，也不参与 `script_time` 或录音起点偏移计算。“开始采集”按钮不得触发权限弹窗。
- 进入准备倒计时后录音选项锁定；启用时随 Session 自动开始和停止，采集中不可手动停止或重新开始。
- 任务 3 实现不得提前制作照片、备注或录音功能。

### 2. 会话与异常操作分区

第二排为：

```text
[暂停播报/继续播报] [跳过] [开始采集/结束采集]
```

实际运行时按钮显示当前可执行动作，不同时显示斜杠两侧文字：

- 未开始：`开始采集`；
- 采集中：`结束采集`；
- 播报运行：`暂停播报`；
- 播报暂停：`继续播报`；
- 未开始且选项关闭：`录音：关`；
- 未开始且选项开启：`录音：开`；
- 采集中启用录音：按钮锁定，证据摘要显示`● 录音中`；
- 采集中未启用录音：按钮锁定，证据摘要显示`未录音`。
- 录音准备、失败或保存结束：按钮锁定，证据摘要显示对应状态。

按钮可用性必须同时有逻辑与视觉反馈：未开始、准备倒计时和采集结束时，“暂停/继续播报”与“跳过”必须灰色显示且不可点击；采集中和播报暂停时恢复对应功能色并可操作。

录音选项只在采集前可切换。进入准备倒计时、采集中和采集结束后，第三个位置均不可操作；采集中不得停止或重新开始录音。`● 录音中` 使用醒目红点，录音失败只显示状态，不要求用户在路测中处理，也不阻断 Session。

### 3. 暂停/继续

- 暂停的是计划播报调度，不是 `script_time`。
- 暂停期间 `script_time` 继续增长。
- 恢复后从暂停的计划播报位置继续。
- 原始 `plan_time` 和脚本时间窗口总时长不变。

### 4. 跳过

- “跳过”只作用于主界面当前已经触发的 Event。
- 尚未触发的下一个 Event 不允许跳过，不存在 `pending → skipped`。
- 当前 Event 确认未执行：`triggered → skipped`。
- 记录 `skip_script_time_us`。
- 已经存在的 `trigger_script_time_us` 必须保留。
- 跳过不得改写 `action` 或原始 `plan_time`。

正常 Event 在计划节点实际触发后自动进入 `triggered`，不需要逐项点击“完成”。

### 5. 开始、结束与 abort

- “开始采集”建立 `start_clock`，并令 `script_time_us = 0`。
- “结束采集”记录 `end_clock` 和最终 `script_time_us`，再进入导出流程。
- 强行中止（`abort`）不增加常驻主按钮；需要时通过明确的二次确认处理，降低误触风险。

## 不增加的主界面复杂度

当前总体布局不增加：

- 常驻 Event 列表；
- 上一项/下一项导航；
- 主界面常驻照片缩略图管理区；
- 主界面常驻备注历史列表；
- 录音文件管理区；
- 录音播放、音量波形和录音时长显示；
- 多页面导航框架。

照片、备注和跳过默认围绕当前 Event。后续任务若证明必须访问历史 Event，再在对应任务中提出最小补充，不提前扩展。

任务 4 已确认唯一的历史照片访问例外：点击证据摘要中的 `照片 N`，进入当前 Session 的照片列表。列表按 Event 分组，提供缩略图、照片标识、事件名称、拍摄 Clock、“耗时”和照片备注入口；点击缩略图进入只有图片与关闭按钮的全屏预览。该二级页面不在主界面增加常驻区域，也不改变既有中央采集执行区。详细合同见[事件照片记录优化设计.md](事件照片记录优化设计.md)。

任务 5 增加第二个历史访问例外：点击证据摘要中的 `备注 N`，进入当前 Session 按 Event 分组的有效事件备注列表。备注在列表中直接显示并提供新增、修改和逻辑删除操作，不增加备注预览页。照片备注继续从照片列表中的具体照片进入。详细合同见[事件与照片备注支持设计.md](事件与照片备注支持设计.md)。

## 与 V2 任务包的覆盖关系

1. 任务 2：保留当前/下一动作、倒计时、开始/结束和后台播报反馈。
2. 任务 3：提供 Clock、连续 `script_time`、暂停/继续播报和跳过。
3. 任务 4：照片摘要兼作列表入口，拍照按钮绑定当前 Event，并提供照片列表与全屏预览。
4. 任务 5：备注摘要兼作 Session 事件备注列表入口，主界面备注按钮绑定当前 Event，照片备注从照片列表进入。
5. 任务 6：采集前使用默认关闭的录音双态选项，采集开始后只显示准备、录音、失败或保存结果，不增加采集中操作。
6. 任务 7：预留导出入口。
7. 任务 8：持久化恢复或失败使用临时提示，不增加常驻区域。
8. 任务 9：兼容与验收由实现和测试保证，不增加界面区域。

## 设计结论

审核通过的主界面采用“既有采集执行区 + 证据操作分区 + 会话控制分区”。该结构能够覆盖当前 V2 任务包所需的主界面入口，不需要为任务 3、4、5 分别重做界面。

任务 4 不另行制作可视化效果图。本文件中的 ASCII 图示及文字约束作为正式界面示意，已经覆盖必要的显示元素、操作入口和状态变化；后续实现以简单、够用和沿用既有界面为原则。

任务 6 沿用同样原则：录音 UI 只复用证据操作区第三个位置和证据摘要状态，不制作额外效果图，不增加录音页面或更多操作。
