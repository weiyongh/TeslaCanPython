# 采集过程全程录音设计

## 1. 目标与边界

任务 6 为可选的采集 Session 提供连续录音，保存车内口述、环境声音和操作背景。录音是 Session 级独立证据，只记录自身时间，不与 Event、照片或备注建立业务绑定。

不实现语音转文字、自动摘要、音频剪辑、降噪处理、多轨录音、录音文件列表、播放、波形或采集过程中手动停止与重启。

## 2. 录音生命周期

```text
采集前：录音关闭 ⇄ 录音开启
                     │
                     ▼
准备倒计时：检查权限与初始化 → 提前开始采集音频
                     │
                     ▼
Session 开始：建立 script_time = 0，录音继续
                     │
          暂停播报、拍照、备注均不影响录音
                     │
                     ▼
正常结束或 abort：停止音频输入 → 完成编码与保存
```

- 每个新 Session 默认 `recording_enabled = false`，不继承上一次选择。
- 录音选项只在采集前可切换；进入准备倒计时后锁定。
- 已启用时目标为一个 Session 对应一个连续录音文件。
- 录音失败不阻止、推迟或中断 Session，也不改变 `script_time` 零点。

## 3. 权限流程

App 在 `AndroidManifest.xml` 声明 `RECORD_AUDIO`、麦克风前台服务类型及目标系统要求的相关权限。

权限仅由采集前点击 `录音：关` 触发检查：

```text
已有权限 → 直接切换为“录音：开”
可以申请 → 显示系统权限框
            ├─ 允许：自动切换为“录音：开”
            └─ 拒绝：保持“录音：关”
永久拒绝 → 提示前往系统应用设置
```

权限申请发生在准备倒计时与 Session 之前，不启动录音、不建立 `script_time`，也不计入录音起点偏移。“开始采集”按钮永不触发权限弹窗。

若录音已开启但权限随后被撤销，Session 照常开始，录音状态记为失败，原因使用 `PERMISSION_NOT_GRANTED`。

## 4. 音频与文件方案

- 输入：Android 原生 `AudioRecord`，默认手机麦克风；
- 声道：单声道；
- 采样率：优先 48 kHz，设备不支持时选择可用的稳定采样率并如实记录；
- 编码：Android 原生 `MediaCodec`，AAC-LC；
- 封装：`MediaMuxer`，M4A/MP4 容器；
- 建议码率：96 kbps，兼顾车内语音质量和长时间文件大小；
- 存储：通过 `MediaStore` 写入用户可见的 `Recordings/CANVoiceRunner/<Session>/`，保存 `content_uri`，不依赖绝对文件路径；
- 第三方依赖：不增加。

使用 `AudioRecord` 而不是只用 `MediaRecorder`，是为了取得音频帧位置和 `AudioTimestamp`，真实记录录音流起点。编码输出的时间戳按累计 PCM 帧数生成，保证文件媒体时间连续。

## 5. 文件命名

以采集脚本原始文件名为主体，移除扩展名，附加“录音”和录音起始 Clock：

```text
脚本：TM3-016_语音执行脚本.txt
录音：TM3-016_语音执行脚本_录音_20260909_153022_615.m4a
```

同一脚本重复采集不得覆盖既有文件。文件名中的非法字符只做安全清洗，原始脚本文件名另存元数据，不因清洗而改变。

## 6. 录音起点与时间

录音起点定义为麦克风采集流中首个有效 PCM 音频帧的估计捕获时刻，不是初始化、调用 `startRecording()`、方法返回或文件创建时刻。静音帧也是有效音频帧。

准备倒计时阶段启动 `AudioRecord`，取得：

- `AudioTimestamp.framePosition`；
- `AudioTimestamp.nanoTime`；
- `AudioTimestamp.TIMEBASE_BOOTTIME`；
- 实际 `sample_rate_hz`。

由稳定时间戳反推流的第 0 帧时间：

```text
audio_stream_start_ns =
    timestamp.nanoTime
    - timestamp.framePosition * 1_000_000_000 / sample_rate_hz

recording_start_offset_us =
    (audio_stream_start_ns - session_start_realtime_ns) / 1000
```

`recording_start_offset_us` 是有符号整数微秒：负值表示录音早于 Session 零点，正值表示存在开头漏录延时，零表示重合。工程准确度目标为正负 20 毫秒，已确认足以服务当前 CAN 数据采集；微秒只是统一存储分辨率。

Android 提供的是系统最佳估计，不能声称覆盖音频硬件内部未知延迟。元数据必须同时保存：

```ini
recording_start_clock
recording_start_offset_us
recording_start_method = AUDIO_TIMESTAMP_BOOTTIME
recording_start_accuracy_us = 20000
sample_rate_hz
```

如果时间戳暂时不可用，录音继续并稍后重试；只要之后取得稳定帧位置，仍可反推第 0 帧。若整段均无法取得可靠时间戳：

```ini
recording_start_offset_us = null
recording_start_method = TIMESTAMP_UNAVAILABLE
```

不得用 API 调用时间冒充首帧时间。

## 7. 录音记录

每个 Session 最多产生一个当前录音记录，至少包含：

```ini
recording_enabled
recording_status
source_script_name
file_name
content_uri
recording_requested_clock
recording_request_offset_us
recording_start_clock
recording_start_offset_us
recording_start_method
recording_start_accuracy_us
recording_end_clock
recording_end_script_time_us
audio_duration_us
sample_rate_hz
channel_count
mime_type
bit_rate
end_reason
failure_clock
failure_script_time_us
failure_reason
```

`recording_status` 至少区分：

```text
DISABLED / PREPARING / RECORDING / SAVED / FAILED / SAVE_FAILED
```

字段不适用时使用 `null`，不得制造虚假时间或成功状态。

## 8. 失败处理

- 权限缺失、初始化失败或启动失败：Session 照常开始，不生成虚假起点，记录失败时间和原因。
- 采集中断：立即显示“录音失败”，Session 继续，不自动重启；若已录部分能够正常封装，则保留部分文件并明确失败状态。
- 存储不足或编码失败：尽力停止并释放音频资源，记录 `SAVE_FAILED` 或对应失败原因。
- 正常结束或 `abort`：停止输入，排空编码器并完成容器；`abort` 产生的可播放录音允许保留，`end_reason` 必须准确。
- App 进程终止按现有约定视为采集失败；跨进程可靠恢复属于任务 8。

## 9. UI 设计

UI 只复用证据操作区第三个位置和证据摘要，不改变既有中央采集执行区。

```text
采集前：     [录音：关] ⇄ [录音：开]
准备倒计时： [录音准备中]  （锁定）
采集中：     [录音中]       （锁定）
未启用：     [本次未录音]   （锁定）
失败：       [录音失败]     （锁定）
结束：       [录音已保存] / [录音保存失败]
```

证据摘要使用 `● 录音中` 明确提示正在使用麦克风。所有采集过程状态均不可点击，不增加录音播放、文件列表、波形或录音计时。正式界面约束同时见[采集现场统一UI交互设计.md](采集现场统一UI交互设计.md)。

## 10. 测试与验收

1. 默认关闭录音，开始 Session 不申请权限、不创建录音文件。
2. 首次开启时正确申请权限；允许后自动开启，拒绝后保持关闭；权限处理不建立 Session 时间。
3. 启用录音后在准备倒计时提前取得音频，Session 开始后连续录制；暂停播报不影响录音。
4. 正常结束和 `abort` 均生成可播放文件，名称包含脚本名和起始 Clock，且不覆盖既有文件。
5. 用 `AudioTimestamp` 反推的 `recording_start_offset_us` 在目标手机上稳定，重复测试的工程误差不超过正负 20 毫秒。
6. 时间戳不可用时保存 `null` 和 `TIMESTAMP_UNAVAILABLE`，不伪造偏移。
7. 权限被撤销、初始化失败、麦克风被抢占、存储不足和编码失败均不阻断 Session，并形成正确失败状态。
8. 前后台切换和锁屏真机测试中录音尽可能连续；系统限制或中断必须可见、可记录。
9. 录音期间拍照、备注、跳过、暂停播报和结束采集功能不被阻塞。
