# 事件与照片备注支持设计

## 1. 问题与目标

现场采集需要用简短文本补充脚本无法表达的实际情况。备注必须绑定明确对象并记录发生时间，同时保持主界面操作简单。

任务 5 支持两类备注：

- 事件备注（Event Note）：一个 Event 可以有多条；
- 照片备注（Photo Note）：一张照片同时最多有一条有效备注。

两类备注复用同一套存储、时间、编辑和逻辑删除机制。任务 5 不增加备注预览页，不实现富文本、附件或跨 Session 管理。

## 2. 统一备注模型

每条备注至少保存：

```ini
note_id = N0001
target_type = EVENT
target_id = E05
text = 充电枪第一次插入没有完全到位
created_clock = 2026-09-09T15:30:25.827+08:00
created_script_time_us = 84827361
updated_clock = null
updated_script_time_us = null
deleted = false
deleted_clock = null
deleted_script_time_us = null
```

- `target_type` 只使用 `EVENT / PHOTO`。
- Event 备注的 `target_id` 为 `event_id`；照片备注的 `target_id` 为 `photo_id`。
- `text` 为纯文本，可以换行；保存前去除首尾空白，空文本不得生成备注。
- `created_clock` 和 `created_script_time_us` 记录新增入口被触发时的真实时间点。只有用户确认保存后才正式生成备注记录。
- `updated_*` 记录最近一次修改确认的时间，不覆盖 `created_*`。
- `deleted_*` 记录逻辑删除确认的时间，不覆盖原文和创建、修改记录。

照片备注使用相同记录结构，但业务约束为同一 `photo_id` 同时最多存在一条 `deleted = false` 的备注。已逻辑删除后可以重新新增；旧记录仍保留为删除审计，新记录使用新的 `note_id`。

## 3. 对象冻结与时间原则

1. 用户点击主界面“备注”时，立即冻结当时的当前 Event 和创建时间锚点；编辑对话框打开期间脚本推进，不得改变备注归属。
2. 用户从照片列表进入备注时，冻结所选 `photo_id` 和创建时间锚点。
3. 暂停播报期间允许新增、修改和删除备注，`script_time` 继续真实增长。
4. 修改时间和删除时间在用户确认对应操作时记录。
5. 照片备注的创建时间表示“填写备注”的时间，不替代照片自身的 `captured_clock` 和 `captured_script_time_us`。
6. 采集正常结束或 `abort` 后，备注列表只读，不允许新增、修改或删除，避免在 `script_time` 已停止后混入现场事件记录。

## 4. UI 设计

不制作额外可视化效果图，以下 ASCII 图示为正式界面示意。

### 4.1 主界面

```text
照片 2    备注 3    ● 录音中
              ↑
       当前 Session 有效事件备注总数及列表入口

[拍照]      [备注]      [开始录音/停止录音]
              ↑
       为当前 Event 新增备注
```

- `备注 N` 只统计当前 Session 中未删除的事件备注，不包含照片备注。
- `备注 N` 点击后进入当前 Session 的事件备注列表；即使 `N = 0`，采集中或暂停中仍可进入空列表并新增当前 Event 备注。
- 主界面“备注”按钮在采集中和播报暂停中可用；未开始、准备倒计时、正常结束及 `abort` 后置灰。

### 4.2 事件备注列表

```text
事件备注                                      [关闭]

Event E05 · 手动下降，按住
[＋ 为当前 Event 新增备注]

N0001  15:30:25  耗时 01:24
充电枪第一次插入没有完全到位
                                      [修改] [删除]

N0002  15:31:08  耗时 02:07
重新插入后已锁止
                                      [修改] [删除]
```

- 显示当前 Session 全部有效事件备注，按 Event 分组；组内按 `created_script_time_us` 正序排列。
- 每项直接显示完整纯文本、创建 Clock 和“耗时”，不再进入预览页。
- 采集进行中时可修改或删除；结束后隐藏或禁用操作按钮，仅供查看。
- 空列表显示“暂无事件备注”，不制造空记录。

### 4.3 新增与修改对话框

```text
新增备注 · Event E05

┌──────────────────────────┐
│ 输入现场情况……           │
│                          │
└──────────────────────────┘

              [取消] [保存]
```

- 使用普通多行文本对话框，不增加格式工具栏。
- 修改复用同一对话框，标题改为“修改备注”，并载入原文。
- 保存失败时保留输入内容并提示失败，不静默关闭。
- 取消新增不生成记录；取消修改不改变原记录。

### 4.4 照片备注

照片列表中的每张照片显示一行备注摘要及入口：

```text
E05-P01  15:30:25  耗时 01:24
[缩略图]  充电枪接口未完全插入……       [修改备注]
```

- 无有效备注时显示“添加备注”；存在有效备注时显示单行摘要和“修改备注”。
- 照片备注使用相同的新增、修改和删除对话框机制。
- 照片文件不可用时，只要元数据仍存在，照片备注仍可查看；采集进行中仍可修改或逻辑删除。
- 照片全屏预览保持只有图片和关闭按钮，不在预览页加入备注操作。

### 4.5 逻辑删除

```text
删除备注？
该备注将从有效列表移除，但保留删除审计记录。

              [取消] [删除]
```

- 删除必须二次确认。
- 确认后设置 `deleted = true`，记录 `deleted_clock` 与 `deleted_script_time_us`。
- 已删除备注不显示在有效列表，也不计入 `备注 N`。
- 不提供现场恢复按钮；原文和全部时间字段继续保留，供任务 7 导出审计。

## 5. 状态与失败边界

1. 新增、修改、删除只允许在采集中和播报暂停中进行。
2. 进入备注列表或对话框不得隐式暂停 `script_time`、脚本计划进度或 TTS。
3. App 进程终止仍按当前约定视为本次采集失败；任务 8 只实现正常 Session 生命周期内的持续落盘，不设计异常恢复。

4. 同一照片的备注新增必须检查是否已有有效记录，避免并发产生两条有效照片备注。
5. 保存、修改或删除失败必须保持操作前状态并提示用户，不生成半完成记录。

## 6. 验收要点

1. 同一 Event 连续新增两条备注，产生不同 `note_id`，均绑定点击入口时的 Event。
2. 编辑框打开后脚本推进，保存结果仍绑定原 Event，创建时间仍为入口触发时间。
3. 修改备注保留 `created_*`，只更新文本和 `updated_*`。
4. 逻辑删除后备注从列表消失、总数减一，但原文及 `deleted_*` 仍可供导出。
5. 一张照片不能同时出现两条有效照片备注；删除后允许新增一条新的有效备注。
6. 暂停播报期间进行备注操作，所有 `*_script_time_us` 仍按真实时间递增。
7. 采集结束后所有备注只读。
8. 备注列表和编辑对话框不影响脚本推进与 TTS。
