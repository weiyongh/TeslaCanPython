# TM3-015/016 扫码充电采集指导

版本：2026-08-31。两项均属于充电系统采集，尚未采集、无实车结论。

## 1. 编号与范围

| 编号 | 脚本 | 诊断问题 |
|---|---|---|
| TM3-015 | [直流快充](../input/TM3-015_直流快充采集脚本.txt) | 插枪与授权后，直流充电请求、许可、实际电流和停止退出如何对应？ |
| TM3-016 | [交流慢充](../input/TM3-016_交流慢充采集脚本.txt) | 插枪与授权后，交流供电、OBC转换、Pack充电和停止退出如何对应？ |

每项独立一份原始ASC，短版默认5分钟，扫码预留1分钟，检查启动后计划观察约2分钟；实际充电通常约2～3分钟，视启动时刻而定，没有最低时长要求，可随时正常停止。目标是“充前背景—开充电小门—插枪—扫码授权—电流建立—短时运行—主动停止—拔枪后状态”，不是全SOC曲线、峰值能力、充满降流、容量/SOH或完整休眠实验。自然充满的停止过程与主动停止分开解释。

热管理自动运行作为充电边界记录，不关闭保护，也不在本轮主动切换温控策略。快慢充先后顺序导致SOC和温度不同，应如实记录，不能直接比较峰值功率或效率。

## 2. 扫码时间与顺延规则（必须提前阅读）

默认时间轴：0～20秒未插枪背景；20秒开充电小门；40秒插枪；60～120秒扫码授权和启动；120秒检查充电状态；150及210秒记录数据；240秒申请停止；270秒确认停充并安全拔枪；300秒结束。开门、插枪和扫码是独立播报节点。

扫码预算为1分钟，不要求等满；提前完成即正常充电。此脚本默认先插枪后扫码，若桩要求先扫码，按桩要求调整顺序，所有实际事件仍分别记录。登录注册提前完成，避免消耗扫码窗口。

定义T为实际开始输送充电电流的时间，以桩/车状态与数据共同核对。240秒仅为默认停止点，取消此前“实际充电至少15分钟”的要求。可以随时从正常停止入口结束，不必凑满时长。启动延迟时不自动顺延充电观察期，由现场自行决定是否短暂等待、立即停止或取消。比如180秒才启动，240秒停止所得60秒数据仍可保留，注明覆盖不足即可。

提前停止或超时后不假定CANVoiceRunner能自动重排节点：忽略不再适用的播报或停止播报计时，X930继续记录，按实际事件完成停充、正常解锁和拔枪。拔枪后建议留存30秒背景，可根据现场情况调整。提前停止可以提前收尾；停充或解锁延迟只顺延安全收尾，不增加最低充电时长。费用以运营商规则和订单为准，本脚本不保证停充后即停止全部计费。

如果桩或车辆正常提前终止，保留实际原因，不重新启动凑时长。扫码授权失败或无法启动时，保留失败数据和提示；按桩说明取消订单、安全释放充电枪，作为失败尝试另存。重试应记录每次请求，不能把重试混成一次正常握手。无需无限等待，也不把平台或网络失败直接判作车辆故障。

## 3. 开始前检查

- 确认车辆可以安全充电；出现高压、充电、过热告警，或插头/线缆破损、焦味、异常发热时，不继续实验，联系车辆维修或场站人员。
- 本项目已报告喇叭不响，不要为了本实验带故障进行额外道路测试；先安排维修或安全到站方案。
- 车辆P挡、已唤醒，充电接口未连接。不要求电池接触器起始断开；若已闭合，本轮不能声称捕获了首次预充。
- 记录充电上限、当前SOC和预约设置，确保有合理充电空间且不会被预约阻止即时充电。不强制充至100%，不为追求功率深度放电。
- 记录快充前是否导航预热、行驶时长、停车时长；慢充记录车辆电流设置、单/三相（能确认才记录）。
- 座舱空调等负载尽量保持固定；人员舒适和安全优先，任何调整记时。电池自动热管理保持正常。
- 停止方式提前确定，遵循本地充电桩及该车辆说明。先正常停止再解锁拔枪；等待时间不能代替安全状态确认。不要使用急停或应急解锁制造试验事件。

## 4. 工具分工与对时

X930全量原始ASC为主证据，提前接好、只监听、不中断记录、不发送诊断或控制报文。存储容量与连续记录时长先检查，避免循环覆盖启动瞬态。

MX+ + Scan My Tesla为可选辅助：在已验证专用线束、供电和并联接线正确的条件下使用，不能为了双设备记录临时乱接分线。如果只能接一套，优先保留X930，辅以桩屏、车屏和订单。两种软件可能使用相近的社区解码定义，显示一致不等于独立硬件测量确认。

建议辅助记录：SOC、Pack电压/电流/功率、可用充电能力、电池温度、低压电压及充电状态。OBC交流输入、直流输出和直流桩参数仅在实际可见时使用，不能假定Scan My Tesla提供所有字段；缺失值写“未覆盖”。本地旧DBC温度定义存在冲突，App温度也应检查合理性，不直接覆盖历史结论。

扫码需要切换支付/场站App，推荐独立设备运行Scan My Tesla和播报。只有一台手机时先验证后台记录不会停；不能保证则不强求Scan My Tesla同步，X930必须持续。MX+不要同时交给多个诊断App。

记录ASC起点、脚本起点、手机录像/日志起点的时钟偏移；记录结束时再核对一次。播报CSV是提示时间，扫码时间、插枪时间和电流建立时间不能直接从它推定。桩屏显示与手机网络响应存在延迟，不用于推定毫秒级CAN响应。

## 5. 快慢充各自关注的证据链

### 直流快充

连接及锁止 → 授权/启动请求 → 充电许可及协商/安全检查（可见项）→ 电压匹配与接触器变化（可见项）→ 直流电流建立 → 请求/允许/实际功率 → 停止请求 → 电流退出 → 连接释放。

记录桩额定电压/电流/功率、共享功率、桩显示电压电流功率、车侧Pack数据及限制原因。第三方桩的协议通信不一定在当前车内CAN域完整可见，缺少握手帧不等于没有握手。直流充电不是OBC交流整流过程。

### 交流慢充

连接及锁止 → 授权与交流供电许可 → OBC工作状态 → 交流输入 → OBC直流输出 → Pack充电 → 停止请求 → OBC退出 → 连接释放。

记录桩侧相数、交流电压/电流/功率、车辆电流设置、OBC可见状态与输出。CP/连接检测等如不在当前CAN域，标记未覆盖；不直接测量充电高压端子。

桩输出功率不必等于Pack净充电功率，差异还可能包括OBC损耗（慢充）、车辆辅助负载、显示滤波及时间错位；未经边界和同步校核，不能用两屏数值直接计算充电效率。停止充电后Pack电流也不必为零，车辆仍可能有高压负载。

## 7. 分析与最小闭环

- 分别保留开充电小门、插枪和扫码授权前后的原始事件及整个启动段；优先记录电流建立，不为等待稳定而额外延长计费。
- 若有连续20～30秒相对稳定窗口，报告其电压、电流和功率范围；没有稳态则按启动/爬升过程分析，不将短样本推广成长期稳态、效率或峰值能力基线。
- 停止尽量保留请求前10秒至安全拔枪后30秒，实际不足时注明覆盖范围；分别分析请求、电流退出、解锁与拔枪，不推造缺失时序。
- 可用SavvyCAN加载ASC和本地DBC先核对原始帧、复用页面及时间；本轮未执行实车分析，分析阶段须在报告中写明实际使用的命令/工具配置和输出路径。
- 已确认、强候选、弱候选、未知分开列出；接触器状态、充电方向与实际功率需交叉验证，当前采集域外的通信不要自动继承语义。
- 结果按“请求—条件—决策—执行—反馈—结果—异常分支”归纳。首轮增量是充电开始/正常运行/主动停止控制链；缺口再决定一个最小验证，不宣称已完成全SOC曲线或容量测试。
