# TM3-007/008 Model 3 完整上下电采集指导

## 1. 编号与诊断问题

| 编号 | 采集主题 | 单份ASC要回答的问题 |
|---|---|---|
| TM3-007 | 开锁、开门、上电 | 车辆从已休眠状态开始，解锁、开门、入座、踩制动和挂D分别触发了哪些唤醒、许可、预充、接触器、READY/ENABLE及DCDC变化？ |
| TM3-008 | 关门、落锁、下电 | 车辆从READY开始，离座、关门和落锁后，高压、DCDC与各网络按什么顺序退出，最终是否进入通信静默？ |

本次采用两个连续编号而不是合并成一个长文件。上电与下电的起始条件、观察窗口和失败判据不同，分开后更容易建立正常基线、重复验证和定位缺失环节。TM3-007、TM3-008均为新实验；不覆盖TM3-002，TM3-002仍代表此前“进入READY”的已有采集。

## 2. 目标证据链

TM3-007按以下链路寻找证据：

```text
解锁/开门/占座请求
→ 低压与网络唤醒
→ 制动条件输入与上电条件检查（HVIL、绝缘、故障与状态许可）
→ 预充与高压母线上升
→ 主接触器状态
→ 挡位请求与反馈
→ 高压可用/READY/Drive Enable
→ DCDC启动与低压母线反馈
```

TM3-008按以下链路寻找证据：

```text
离座/开门/关门/落锁请求
→ 门锁与车身状态反馈
→ READY或高压需求撤销
→ 扭矩/充放电许可退出
→ 接触器与高压母线变化
→ DCDC状态变化
→ 控制器分批停止通信
→ 网络静默/休眠候选
```

没有DBC覆盖的环节只记录候选ID、字节/位、变化方向和时序，不确认具体语义。

## 3. 正式采集前准备

### 3.1 车辆条件

- 车辆停在安全、平坦、通风处，P挡，未连接充电枪。
- 记录车型年份、当前车辆软件版本、SOC、环境温度和可获得的电池温度。
- 关闭空调、座椅加热、除霜、灯光等非必要负载。
- 关闭哨兵模式、温度保持、露营模式、爱犬模式、预设温度和座舱过热保护；记录无法关闭的功能。
- 建议使用钥匙卡完成解锁和落锁，避免手机钥匙靠近车辆造成提前唤醒。
- 不使用Tesla App确认车况；打开App本身可能唤醒车辆。

### 3.2 采集链路

- 记录CAN接入位置/采集域、通道、波特率、采集硬件、固件及软件版本。
- 采集器必须处于只监听模式，不发送探测帧、诊断请求、心跳或周期报文。
- 先做一次“采集器保持连接能否休眠”的空白验证。若连接后总线始终活跃，本轮不能宣称采到真实休眠。
- 采集器需要能在车辆外持续记录，并最好支持定时停止或远程停止；停止动作不能依赖开门或靠近车辆。
- CANVoiceRunner只负责播报和生成实际触发时间CSV。若运行它的手机同时是手机钥匙，应关闭该设备的Tesla手机钥匙能力，或改用不绑定车辆的播报设备。

### 3.3 文件准备

将以下脚本载入CANVoiceRunner并先空运行一次：

- `input/TM3-007_开锁开门完整上电采集脚本.txt`
- `input/TM3-008_关门落锁完整下电采集脚本.txt`

每次实验保留脚本版本、原始ASC、App实际触发时间CSV和现场记录，四者使用相同实验编号。

## 4. 推荐执行顺序

### 4.1 TM3-007：开锁、开门、完整上电

1. 提前连接并启动只监听采集器，锁车后将所有有效钥匙和手机带离车辆。
2. 至少静置30分钟；实际休眠以总线通信显著下降/静默为证据，不只依赖等待时间。
3. 在不触碰车辆、不打开Tesla App的情况下开始脚本时间轴。若采集器从静置前已连续记录，后处理时以脚本CSV对齐事件。
4. 按脚本依次执行钥匙卡解锁、等待、开驾驶门、入座、关门、踩制动。
5. 单独踩制动只标记为条件输入，不据此判定READY；继续踩住制动挂入D挡并保持车辆完全静止10秒，以挡位反馈和驱动许可确认可工作状态。
6. 持续踩住制动挂回P挡，随后松开制动，留出30秒稳定窗口再结束。

关键点：若必须靠近采集器才能按“开始”，靠近动作本身可能污染休眠基线。应改用预先连续记录、定时任务或不会携带有效钥匙的助手操作。

### 4.2 TM3-008：关门、落锁、完整下电

1. 建议另存一份新ASC，不与TM3-007拼接；开始时车辆已正常READY、P挡稳定。
2. 按脚本离座并开门、关门等待、使用钥匙卡落锁。
3. 落锁后人员和全部钥匙至少离车10米，不打开Tesla App，不再触碰车辆。
4. 连续记录至少10分钟。若容量允许，建议延长到20～30分钟，以确认迟发休眠；延长时不要修改前600秒事件标记。
5. 优先通过定时/远程方式停止记录。若只能人工接近，必须把“接近车辆时间”写入现场记录，接近后的报文不得用于判断自然休眠。

关键点：落锁、高压下电、DCDC退出和CAN网络休眠不是同一个时刻。600秒仍有报文不自动等于故障，也可能是车辆策略、某个功能、钥匙、采集器或采集域导致。

## 6. 采集成功判据与证据等级

TM3-007的最低成功条件：起始具有可解释的休眠/低通信窗口；解锁、开门、入座、踩制动、挂D和挂回P挡均有实际时间标记；挂D成功且车辆保持静止，并通过挡位反馈、驱动许可或车辆实际显示确认进入正常可工作状态。单独踩制动不作为READY判据。捕获到预充、接触器和DCDC信号可形成更强证据，但DBC缺失时不能以猜测补齐。

TM3-008的最低成功条件：起始READY稳定；开门、离座、关门、落锁有实际时间标记；落锁后有不少于10分钟无干预窗口；记录是否观察到高压/DCDC退出及网络通信下降。

结论分级：

- 已确认：DBC定义、物理现象和重复实验时序一致。
- 强候选：与目标动作重复同步，方向和控制逻辑合理，但缺少完整DBC或独立反馈。
- 弱候选：只在单次事件附近变化，可能受其他控制器或周期状态影响。
- 未覆盖/未知：当前采集域、DBC或硬件无法观察，必须保留为空白。

## 7. 建议重复与异常处理

- 两个编号各至少重复两次；重复文件可加`_R1`、`_R2`，不要占用新TM3编号。
- 若TM3-007在接近车辆前已经恢复大量通信，检查手机钥匙距离、App后台活动、哨兵/温控功能和采集器主动通信。
- 若踩制动或挂D前车辆已完成高压上电，按事实记录；这可能说明开门、入座或车辆策略已建立高压需求，不能强行把踩制动或挂D解释为唯一的高压上电请求。READY/ENABLE仍应使用挡位反馈、驱动许可或车辆实际显示独立确认。
- 若TM3-008长时间不休眠，先把结果标为“休眠未确认”，再设计最小排查实验，不人为断开HVIL、低压电池或高压部件。
- 任何异常提示、车辆状态不明或现场不安全时立即中止；不为追求时间点而继续操作。

## 8. 采集后最小闭环

每个编号单独输出：适用条件、实际动作时间、ASC与分析命令、请求—条件—决策—执行—反馈—结果证据链、正常变化方向与关键时序、证据等级、对上/下电控制树的增量，以及一个最小下一步验证实验。跨采集域的候选分数和语义不得直接迁移。
