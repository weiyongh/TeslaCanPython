# Model 3 CAN数据采集

## 1. 目的

本阶段以Tesla Model 3作为正常基准车型，为新能源诊断L3建立可复现的核心数据基线。第一轮采用分离采集，每份ASC只回答一个主要诊断问题，便于DBC解码、无DBC候选遴选、SavvyCAN人工查看以及后续与控制树逐项核对。

本阶段不是完整逆向Tesla私有CAN，也不要求一次覆盖控制树中的全部变量。先完成“进入工作状态—驱动许可—正扭矩—负扭矩—动力电池能力边界”的最小闭环，再根据采集结果补充缺失环节。

## 3. 与语音播报App的兼容约定

所有脚本均采用UTF-8文本和以下格式：

```text
20s   操作标题
      现场说明
      记录要求
```

Android语音播报App解析带时间戳的标题行。App会在计划动作前5秒播报“准备，操作标题”，最后3秒倒计时，并在计划时刻发出执行音。缩进行是现场说明和事后追溯信息，不作为独立计时节点。

开始正式实验前，应在安全环境中载入脚本并空运行一次，确认中文TTS、音量、时间节点和动作描述均可正常使用。

## 4. 第一轮核心观察量

### 4.1 动力电池系统

- SOC、包电压、包电流和电池功率；
- 单体最高/最低电压、压差及对应编号；
- 电池最高/最低温度和温差；
- 最大允许放电、充电和回收功率；
- 放电许可、充电许可、回收许可和高压可用；
- HVIL、绝缘、预充、接触器及故障等级；
- BMS工作状态和功率限制原因。

### 4.2 电驱系统

- READY、制动状态、挡位请求和实际挡位；
- Drive Enable、Drive Inhibit及限制原因；
- 加速踏板位置和驾驶员扭矩请求；
- VCU目标扭矩、MCU可用扭矩和实际扭矩；
- 电机转速、车辆速度和轮速；
- 高压母线电压、逆变器电流及功率；
- MCU、逆变器和电机温度；
- MCU运行、保护和故障状态。

并非所有变量都一定能从当前DBC或采集接口获得。无法取得的变量应标记为“未覆盖”，不能根据相邻信号直接假定其值。

## 5. 文件与记录约定

建议原始ASC名称沿用实验编号和主题，例如：

```text
TM3-002_进入READY_YYYYMMDD_HHMMSS.asc
TM3-003_静止挂挡_YYYYMMDD_HHMMSS.asc
TM3-004_低速加速_YYYYMMDD_HHMMSS.asc
TM3-005_低速松电门回收_YYYYMMDD_HHMMSS.asc
TM3-006_动力电池静态基线_YYYYMMDD_HHMMSS.asc
```

每次采集至少同时记录：

- 车辆年份、软件版本和驾驶模式；
- SOC、环境温度和可获得的电池温度；
- 空调、充电、哨兵等可能影响能量状态的功能；
- CAN接入位置、通道、波特率、采集硬件和软件版本；
- 实际动作时间与脚本时间的偏差；
- 路面坡度、目标速度和任何异常现象。

App导出的实际触发时间CSV应与原始ASC一起保留，作为后续事件窗口定位依据。

## 6. 安全与实验边界

- 静止挂挡、低速加速和回收实验只在合法、封闭、平坦且无其他交通参与者的安全区域进行；
- 驾驶员始终以车辆控制和现场安全为最高优先级，无法按脚本执行时立即中止动作；
- 不进行急加速、急制动、高速、低附着或ESP/TCS介入实验；
- 不人为断开HVIL、制造绝缘异常、接触器故障或其他高压故障；
- 上电实验不强求从完全休眠开始。若未采到唤醒、预充或接触器瞬态，应准确记录采集起始状态，不影响后续控制树主干分析。

## 7. 采集后的核对方法

每份数据按以下顺序复盘：

1. DBC已知变量是否覆盖目标控制链；
2. 请求、许可、能力、执行和反馈是否能在时间线上对应；
3. 主要变量的方向、范围、稳态值和响应时间是否合理；
4. 哪些变量已确认、哪些只是候选、哪些完全缺失；
5. 现有证据能够补充控制树和功能诊断树的哪些节点；
6. 缺失节点是否值得设计一个最小补充实验。

只有重复实验中稳定复现，并且与物理现象、DBC定义和控制逻辑相互一致的结论，才进入正式正常基线。
