# 特斯拉车门 DBC 名词解释

## 问题背景

在阅读特斯拉车门相关的 DBC 定义时，会看到 `Latch`、`Handle`、`IntSwitch`、`RelActuator` 等名词，并且部分名称带有 `Front` 和 `Rear` 标识。

容易产生的疑问是：一扇车门通常只有一个把手和一个车内开门按钮，为什么这些部件还会区分前后？

## Front / Rear 的含义

DBC 名称中的 `Front` 和 `Rear`，通常不是指同一扇车门上的前部和后部，而是在区分车辆的前门与后门。

例如，以车辆左侧为例：

| DBC 名称示例 | 实际含义 |
|---|---|
| `FrontLeftLatch` | 左前门的门锁闩/门锁机构总成 |
| `RearLeftLatch` | 左后门的门锁闩/门锁机构总成 |
| `FrontLeftHandle` | 左前门外把手 |
| `RearLeftHandle` | 左后门外把手 |
| `FrontLeftIntSwitch` | 左前门车内电子开门按钮 |
| `RearLeftIntSwitch` | 左后门车内电子开门按钮 |

因此，单独看一扇车门，通常具有一个外门把手、一个主要的车内电子开门按钮，以及一个门锁闩/门锁机构总成。`Front`、`Rear` 与 `Left`、`Right` 组合起来，用于定位具体是哪一扇门。

## 核心名词

### Latch

`Latch` 指门锁闩或门锁机构总成，不应简单理解成“插销”。

车门关闭时，安装在车门上的 latch 会咬合车身门柱上的 striker（锁扣环）。Latch 总成还可能包含门状态检测、锁止/解锁、电动释放相关机构或传感器。

在分析 CAN 信号时，可先将 `Latch` 理解为：

> 这扇门的门锁闩/门锁机构总成及其相关状态。

它不一定只代表车门的“打开”或“关闭”状态，具体含义仍需结合信号定义和值表判断。

### Handle

`Handle` 指车外门把手，是从车外发起开门操作的输入或请求源。

### IntSwitch

`IntSwitch` 可理解为 `Interior Switch`，指车内电子开门按钮，是从车内发起开门操作的输入或请求源。

### RelActuator

`RelActuator` 通常是 `Release Actuator` 的缩写：

- `Rel` = `Release`，释放或解闩
- `Actuator` = 执行器
- `RelActuator` = 释放执行器或解闩执行器

它的作用是驱动门锁闩释放，使车门能够打开。

`Latch` 与 `RelActuator` 的区别是：

- `Latch` 是被锁止或释放的门锁闩/门锁机构总成。
- `RelActuator` 是促使门锁闩释放的电气执行机构。

### HandlePWM

`HandlePWM` 表示某个与车门把手有关的 PWM（脉宽调制）占空比。DBC 将其换算为百分比，是因为 PWM 通常用一个周期内高电平所占的时间比例表示：

```text
占空比 = 高电平持续时间 ÷ PWM 周期 × 100%
```

仅凭 `HandlePWM` 这个名称，无法确定它具体属于以下哪一种信号：

- **状态反馈**：把手传感器通过不同的 PWM 占空比编码把手位置、操作状态或故障状态。此时，百分比不一定代表“把手弹出了多少”，也可能只是若干离散状态的编码值。
- **驱动输出**：控制器向把手电机或执行器输出的 PWM 驱动占空比，用于调节执行器的输出功率或驱动力。

如果它属于输出侧，更专业、准确的叫法是 **PWM 驱动输出** 或 **执行器驱动命令**，而不是“请求强度”。“请求”通常表达是否希望执行某个动作；“驱动输出”才是控制器实际施加给执行器的输出。

可以结合以下信息判断 `HandlePWM` 的性质：

- 报文的发送 ECU 和接收 ECU；
- DBC 中的注释、单位、范围和值表；
- 解锁、把手弹出或收回过程中的数值变化；
- 是否同时存在 `HandleRequest`、把手位置、电机电流、故障状态等相关信号；
- 正常车门与故障车门在相同操作下的时序差异。

典型现象包括：

```text
操作前保持某个非零值，操作后跳到另一个固定值
→ 更像传感器的状态编码

收到弹出命令后短暂升高，动作完成后回到 0%
→ 更像执行器的 PWM 驱动输出
```

在排查“把手没有弹起”的故障时，`HandlePWM` 可以帮助判断问题位于控制请求之前、驱动输出阶段，还是动作反馈阶段，但通常不能单独确定故障原因。最好同时对比弹出请求、把手位置反馈、电机电流、供电和故障信号：

```text
正常门：弹出请求 → PWM 变化 → 位置反馈变化 → 把手弹出
故障门：弹出请求 → PWM 变化 → 位置反馈不变
```

后一种情况说明控制器可能已经发起驱动，但执行结果异常；仍需结合电流和供电，继续区分机械卡滞、电机故障、断路或插头问题。

## 车门打开的控制链

`Handle` 和 `IntSwitch` 是两种不同的开门请求源：

- 车外人员操作 `Handle`，产生外部开门请求。
- 车内人员操作 `IntSwitch`，产生内部开门请求。

控制器收到请求后进行条件判断，例如检查车辆状态、门锁状态或安全限制。允许开门时，控制器驱动 `RelActuator`，由它释放 `Latch`，随后车门可以打开。

```text
Handle / IntSwitch
        │
        ▼
   控制器判断
        │
        ▼
  RelActuator
        │
        ▼
      Latch
        │
        ▼
    车门打开
```

也可以按请求来源展开：

```text
人的操作
   │
   ├── Handle       车外门把手
   │
   └── IntSwitch    车内电子开门按钮
          │
          ▼
      控制器判断
          │
          ▼
   RelActuator      释放/解闩执行器
          │
          ▼
       Latch        门锁闩/门锁机构总成
          │
          ▼
       车门打开
```

## CAN / DBC 分析提示

在一次车内按钮开门操作中，理论上可能观察到以下信号时序：

```text
IntSwitch 状态变化
        ↓
RelActuator 动作或命令变化
        ↓
Latch 状态变化
```

从车外开门时，则可能先观察到 `Handle` 信号变化。实际车辆中的信号顺序、名称和状态值，应以对应车型、软件版本及 DBC 定义为准。

## 核心结论

- `Front / Rear`：表示前门/后门，不表示同一扇门上的前后位置。
- `Latch`：门锁闩/门锁机构总成。
- `Handle`：车外门把手，是外部开门请求源。
- `IntSwitch`：车内电子开门按钮，是内部开门请求源。
- `RelActuator`：`Release Actuator`，即释放/解闩执行器。
- `HandlePWM`：与把手有关的 PWM 占空比；可能是状态反馈，也可能是执行器的 PWM 驱动输出，不能仅凭名称确定。
- 输入侧通常称为开门请求、按键状态或位置反馈；输出侧通常称为驱动输出或执行器命令。
- 基本控制链：`Handle / IntSwitch → 控制器判断 → RelActuator → Latch → 车门打开`。
