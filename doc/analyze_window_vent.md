# analyze_window_vent.py

该程序不依赖 DBC，使用采集脚本中的重复“通风/关闭”动作，对 ASC 中每个 CAN ID 的字节和 bit 进行筛选。

## 使用

```powershell
python src\analyze_window_vent.py `
    input\can_车窗通风采集脚本.txt `
    input\can_20260824154441.asc
```

程序会在 `output` 目录生成：

- `*_车窗通风分析报告.md`：稳定窗口、bit 排名和整字节候选。
- `*_车窗通风bit候选.csv`：可供 Excel 继续筛选的全部 bit 候选。

## 分析逻辑

程序自动识别脚本中的通风和关闭动作，排除动作后的执行时间及稳定区间边缘，然后比较：

- 两次通风后的稳定值是否一致；
- 三次全关时的稳定值是否一致；
- 通风和全关状态是否相反；
- 每次动作附近是否发生翻转；
- 非动作时间是否存在大量背景翻转；
- 各窗口主值占比是否达到 `--min-purity`。

稳定状态不同的 bit 标记为“稳定状态”；只在动作附近重复翻转的 bit 标记为“瞬时请求候选”。

## 参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--settle` | 5 | 动作后等待车辆执行完成的秒数 |
| `--edge` | 2 | 从每个稳定区间两端排除的秒数 |
| `--response` | 5 | 动作后的响应观察窗口 |
| `--min-purity` | 0.95 | 一个稳定窗口中主值的最低占比 |
| `--top` | 30 | Markdown 报告最多展示的候选数 |
| `--output-dir` | output | 输出目录 |

## 限制

统计相关不能单独证明信号含义。车辆唤醒、电源状态也可能与车窗操作同步，候选仍应结合 DBC、原始帧以及单窗/开门/仅唤醒等负对照实验验证。
