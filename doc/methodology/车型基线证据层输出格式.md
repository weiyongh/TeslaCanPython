# 车型基线证据层输出格式

适用：实车采集向车型投射/车型诊断基线库积累数据。TM3-009为首个样例；本版只增加输出附件，不修改原始数据、DBC、现有底层分析或已审核的最终报告。

## 文件分层

| 层次 | 文件 | 读者首先获得什么 |
| --- | --- | --- |
| 简洁正文 | 最终报告.md（允许保留现有编号前缀） | 综合诊断判断：按证据→判断→结论解释发生了什么、是否符合本次工况预期、为什么 |
| 基线证据 | 采集时间线与关键Signal.md | 实际何时发生动作、各控制节点当时的物理值及相互对应关系 |
| 基线证据 | DBC关键Signal覆盖与可读性.md | 哪些节点可观测、Signal如何解释、哪些值不能采用 |
| 工程审计 | 工程审计.md及关联明细 | 原始帧、定义、解码错误、采样、筛选与统计的完整复现 |

控制链、动力响应、能源响应分别呈现、相互印证，不串成单一时间因果链。基线采集用“基线用途/控制关系”，不把全文改写成故障结论。

计划动作与实测结果存在偏差时，最终报告须给出“结论与建议”，至少回答：已获得的哪部分可保存为条件化基线、哪部分只能保留为过程证据、是否需要补采、最小补采范围及补采判据。一个子工况不合格时，不要求重复已经获得合格样本的其他子工况。补采窗口以实际状态或实际测量量进入并稳定在目标条件为起点，不直接采用脚本预定时间；建议时长和SOC、温度、道路坡度/方向、空调等条件记录要求按工况明确写出。

“三个实验问题”仅为TM3-009训练阶段校准分析思路的显式检查项，不作为通用报告的固定章节或固定问题数量。Codex应根据实验目的、控制树片段和状态机自主生成内部诊断问题，核对证据与控制关系并完成自检；最终报告将答案综合为“诊断判断”，按“证据→判断→结论”自然表达。只有实验脚本本身明确提出需要逐项回答的问题时，才保留“问题—回答”形式。四层分析逻辑不要求机械设为正文标题；基线采集中的判断仍服务于控制关系与车型基线结论，不转为车辆故障判定。TM3-009已有问答章节是训练回归样本，不是后续通用模板。

## 采集时间线与关键Signal.md

先给车辆、采集域、源文件和时间基准，再用事件编号关联三张表，避免一张过宽的表：

1. 时间线：事件编号、ASC实际时间、脚本名义时间、实际状态/动作、数据识别判据。
2. 控制/动力：事件编号、时间、挡位/使能、电门、请求扭矩、实际扭矩、轴速/车速。
3. 同事件能源/制动：事件编号、电驱功率、Pack电压/电流/功率、制动输入物理量、制动及相关状态。

每列明确对应Signal、CAN ID和单位。额外状态、SOC、能力等按工况选取，既可加入表格，也可按事件编号保存到关联明细。不只保存扭矩和峰值；保留初始状态、动作边沿、关键过程点、恢复/结束状态及变量对应关系。

事件时间由实际数据识别；脚本时间用于对照，不替代实测。未取得触发记录时不声称精确同步。阈值注明是分析识别条件还是已验证的车辆控制阈值。制动、调速等独立工况单列，不能混入纯加速或稳态统计。

各Signal保留真实采样时间、样本年龄、单位、来源；跨报文使用有时效上限的过去最近样本，不补未来值、不把未采到写成零。事件行不是所有报文同时采到。每个峰值单独定位，不能将各自峰值拼成一个状态。派生量注明公式和输入采样关系；Pack功率优先由同帧V×I计算，明确符号约定。

关联CSV：`events.csv`保存事件定义；`event_signal_samples.csv`保存事件编号、事件时间、Signal、CAN ID、值、原生采样时间、年龄、单位、来源、可用状态。该CSV是补充追溯，不能替代Markdown中的核心物理值。

## DBC关键Signal覆盖与可读性.md

按控制树角色分组：输入、条件/状态/能力、仲裁后请求、执行、运动、能源、制动或其他本工况相关节点。不能仅按名称关键词筛选。

每个Signal至少提供：角色、Message、Signal、CAN ID、单位、DBC来源、DBC声明DLC、Signal需要长度、ASC实际DLC、解码结果/样本数、是否变化、有效观测范围或关键状态、用途。完整定义与采样统计可放工程明细。

分别判断以下情况：

- DBC声明长度不足，但实车字节足够：明确标记，记录采用的解码方法和长度；不修改源DBC，不把技术性可读等同语义已确认。
- ASC短于DBC：按Signal所需字节检查，不把整条Message全判失败或全判有效。
- DBC根本没有Signal：标记缺定义；若采用另一版本，列出具体来源，不能称作给旧定义补长。
- INVALID、SNA、未初始化、解码失败、无帧、复用未出现：分别记录，不混为零、不当成有效物理范围。
- 同名/同位段的不同DBC定义：比较位宽、符号、缩放、偏置、单位、枚举和复用条件；候选对照不自动确认为相同语义。
- 相互矛盾的状态或无法验证的能力字段：保留数值与冲突，说明是否采用，不直接作车辆故障或限制阈值结论。

关联CSV：`signal_coverage.csv`保存覆盖表与精确定义；`dbc_definition_comparison.csv`保存逐版本对照。校验文件记录源文件SHA256、复核结果和受保护文件未变校验。

## TM3-009样例与复现

样例目录：`output/TM3-009/report_v1/`。独立输出脚本：`src/report_tm3_009_baseline.py`。

```sh
.venv/bin/python src/report_tm3_009_baseline.py
```

本版是绑定该采集及已审核DBC的样例生成器，不宣称已实现任意车型自动事件分类。确认格式后，再考虑接入通用最终输出层；现有工程审计能力和原始结果保留。
