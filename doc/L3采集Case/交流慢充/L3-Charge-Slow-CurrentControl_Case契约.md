# L3-Charge-Slow-CurrentControl Case契约

**Case ID：** `L3-Charge-Slow-CurrentControl`  
**用途：** 正常交流慢充电流控制关系基线  
**形成日期：** 2026-09-10  
**当前状态：** 已审核通过  

## 1. Case目标

在正常交流充电已经建立并稳定的前提下，改变操作者可调的充电电流设置，验证实际交流取电响应是否随设置降低、保持和恢复而发生方向一致、时间对应且可区分的变化。

```text
人工调整充电电流设置
→ 设置被接受
→ 经过合理响应时间
→ 实际交流电流或功率产生方向一致的变化
→ 新状态形成稳定窗口
```

## 2. Case范围

本Case包含：

```text
正常充电稳定状态
→ 调低充电电流设置
→ 实际交流取电响应下降
→ 较低设置下短时稳定
→ 恢复原设置
→ 实际交流取电响应上升
→ 恢复设置下短时稳定
```

本Case不负责重新证明完整慢充生命周期，不验证桩侧主动改变允许电流，不验证热降额、SOC降额、异常限流或具体限制来源。

## 3. Evidence Requirements

| ER | 名称 | 必须证明的核心事实 |
| --- | --- | --- |
| ER-01 | 初始控制基准成立 | 调整前存在设置明确、实际交流取电已经建立并短时稳定的初始状态 |
| ER-02 | 有效调低输入成立 | 系统接受并保持了一个明确低于调整前实际充电水平、具有判别力的电流设置 |
| ER-03 | 调低响应成立 | 调低设置后，实际交流电流或功率经过合理响应时间产生方向一致、可区分的下降 |
| ER-04 | 低设置状态保持 | 较低设置下充电没有退出，并形成区别于调整瞬态的短时稳定状态 |
| ER-05 | 恢复响应成立 | 恢复原设置后，实际交流电流或功率相对低设置状态产生方向一致、可区分的上升 |
| ER-06 | 恢复状态保持 | 恢复设置后重新形成稳定充电状态，且过程中没有通过停止、重启或重新连接建立新的充电过程 |

## 4. Observable Requirements

OR从ER和L3电流控制关系产生，优先保留输入、实际响应、时间关系和稳定窗口之间的联合观察。

```text
设置变化
↔ 实际交流电流或功率响应
↔ 响应前后的稳定状态
```

| ER | OR | 需要观察的现象或关系 |
| --- | --- | --- |
| ER-01 | OR-01.1 | 调整前充电电流设置能够确认并记录 |
| ER-01 | OR-01.2 | 调整前实际交流电流或功率形成稳定观察窗口 |
| ER-02 | OR-02.1 | 调低动作前后的设置值能够分别定位 |
| ER-02 | OR-02.2 | 调低后的设置值低于调整前实际充电水平，并留有可判别余量 |
| ER-02 | OR-02.3 | 调低后的设置已被接受并保持 |
| ER-03 | OR-03.1 | 调低前后的实际交流电流或功率能够前后对照 |
| ER-03 | OR-03.2 | 实际响应发生在调低事件之后，并允许合理的控制响应和观察延迟 |
| ER-03 | OR-03.3 | 响应变化量能够区别于观察分辨率和调整前正常波动 |
| ER-04 | OR-04.1 | 低设置阶段存在连续、非瞬态的稳定观察窗口 |
| ER-04 | OR-04.2 | 低设置保持期间连接未解除、充电未退出 |
| ER-05 | OR-05.1 | 恢复动作及恢复后的设置值能够准确定位 |
| ER-05 | OR-05.2 | 恢复后的实际交流电流或功率相对低设置窗口上升 |
| ER-05 | OR-05.3 | 恢复响应发生在恢复事件之后，并允许合理的控制响应和观察延迟 |
| ER-06 | OR-06.1 | 恢复设置后存在连续、非瞬态的稳定观察窗口 |
| ER-06 | OR-06.2 | 初始、低设置和恢复后三个窗口可以在同一Round内对照 |
| ER-06 | OR-06.3 | 三个窗口之间没有发生停止、重新启动或重新连接 |

## 5. Case边界

- Case契约不包含Vehicle ID或具体车型名称。
- 操作者设置值是外部可控输入，不直接等同于内部允许能力或内部电流目标。
- 本Case的核心必需证据是“设置变化—实际交流取电响应—稳定窗口”；Pack侧响应只作为下游增强证据，不是ER完成条件。
- 实际响应只要求方向一致且时间关系合理，不要求与设置变化同步发生。
- 现场设施、设置入口、显示能力、具体阶跃值和记录方式作为共享实现接收的现场条件输入，不属于本Case语义。
- Event、Experiment Plan和VoiceRunner Script由共享实现根据已审核Case契约及现场条件生成。
- Candidate Signal与DBC在Case契约审核并冻结后进入后续可观测性评估与Evidence Mapping，不得反向改写Case、ER或OR。
