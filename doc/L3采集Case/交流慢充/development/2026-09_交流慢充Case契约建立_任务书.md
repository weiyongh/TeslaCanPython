**任务名称：** L3慢充采集脚本生成  
**开始时间：** 2026-09-10 12:30:44 CST  
**当前阶段：** 设计  
**文档状态：** 已审核通过  

## 1. 任务背景

TeslaCanPython通过实车采集完成L3知识的车型实例化和Evidence验证。采集脚本不是孤立的TTS文本，而是把L3验证需求转化为现场动作和可追溯Event的操作入口。

本任务先用一个真实Case建立最小、可用的生成链路，不一次性生成全部慢充脚本，也不建设通用脚本生成平台。

## 2. 第一阶段目标

```text
Case    = L3-Charge-Slow-FullCycle
Vehicle = TESLA-M3-SOP5
用途     = 正常慢充完整生命周期基线
```

建立并验证以下转换链路：

```text
L3 Knowledge
→ Case
→ Evidence Requirement
→ Observable Requirement
→ 现场可观察事实与联合观察关系
→ Experiment Event
→ Experiment Plan
→ VoiceRunner Script
```

第一阶段先证明这条链路能够形成合理、够用、现场可执行且便于后续分析的采集设计。Candidate Signal不是该链路的前置环节，待本阶段设计审核并冻结后，再进入后续可观测性评估和Evidence Mapping。

本任务的原始启动要求见[原始启动约定](2026-09_交流慢充Case契约建立_原始启动约定.md)。

## 3. 任务要求

### 3.1 语义方向

1. Experiment Plan是语义根，VoiceRunner脚本是现场执行与Event追溯的操作根。
2. Case由L3验证需求产生，不由车型、DBC或Signal产生。
3. ER只规定Case完成后最低限度必须证明什么功能事实，不复制控制树或内部实现。
4. OR依据L3功能主线、状态迁移和控制关系，确定为判断ER是否成立而需要观察的现象、前后对照和联合关系。
5. 现场观察手段根据已定义的OR设计，包括操作者可直接确认的车辆状态、车机或充电设施显示、照片和备注；它们可进入Event与Experiment Plan，但不与Candidate Signal合并为同一概念。

### 3.2 Candidate Signal后续阶段边界

1. Candidate Signal Mapping属于第一阶段设计审核和冻结之后的可观测性评估与Evidence Mapping，不是生成ER、OR、Event、Experiment Plan或VoiceRunner Script的前置输入。
2. DBC只能针对已定义的OR寻找Candidate Signal并评估CAN侧可观测性，不得反向生成或自动改写Case、ER、OR和实验设计。
3. Candidate Signal缺失、冲突或不可读只表明CAN侧可观测性不足；如因此怀疑上游设计存在缺口，必须作为独立问题返回人工审核，不得自动回写。
4. Candidate Signal未经实车验证和人工审核，不得提升为Evidence。

### 3.3 现场脚本

1. Event只描述人工动作、现场观察以及拍照、备注等记录节点。
2. 不把预计的车辆内部状态、CAN变化或控制器实现写成已发生事实。
3. 保持CANVoiceRunner当前“播报—人工执行—观察—记录”的工作方式，不设计自动CAN条件状态机。
4. 现场表达参考TM3-015的工作单风格：节点少、动作清楚、观察够用，必要的安全和异常规则说清楚即止。
5. 不可控等待允许暂停或顺延；Planned Time不得冒充VoiceRunner Event Time或CAN Observed Time。

### 3.4 FullCycle范围

```text
未连接
→ 连接识别
→ 充电准备/许可推进
→ 实际交流供电建立
→ 车辆侧功率转换
→ Pack真实充电结果
→ 短时保持
→ 正常停止
→ 安全断开与退出
```

本Case不覆盖预约充电、电流阶跃、长时间热稳定、达到SOC上限自动停止、故障注入或异常拔枪。

## 4. 第一阶段输出

1. FullCycle Experiment Plan；
2. CANVoiceRunner可执行脚本；
3. `ER ↔ OR ↔ 实验观察窗口 ↔ Event`追溯关系；
4. `Event ↔ 现场照片 / 备注 / 显示读数`等外部现场观察和记录要求；
5. 必要的设计自检和人工审核记录。

第一阶段不输出Candidate Signal Mapping、CAN侧可观测性评估、Evidence Assessment、Signal语义确认、诊断判断、车型基线结论或其他慢充Case的正式脚本。

## 5. 原始验收场景

```text
以TESLA-M3-SOP5在小区商用交流慢充桩完成一次正常FullCycle：
未插枪背景
→ 插枪后暂不扫码
→ 微信扫码启动
→ 实际充电建立
→ 短时保持
→ 正常停止
→ 确认停止后拔枪
→ 断开后背景
```

采集应保留VoiceRunner Event时间、ASC、Tesla车机照片、桩屏或微信小程序证据及必要备注，使后续分析能够从ER追溯到本轮原始采集。

## 6. 完成边界

任务书和设计方案形成后停在“等待设计审核”。未经人工审核，不进入Candidate Signal Mapping、CAN侧可观测性评估、程序开发、模板修改、正式脚本发布或其他Case设计。
