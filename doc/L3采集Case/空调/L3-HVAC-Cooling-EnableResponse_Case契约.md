# L3-HVAC-Cooling-EnableResponse Case契约

**Case ID：** `L3-HVAC-Cooling-EnableResponse`  
**用途：** 正常空调制冷启停控制关系基线  
**形成日期：** 2026-09-11  
**当前状态：** 已审核通过  

## 1. Case目标

验证正常静止条件下，人工开启制冷后，系统能够建立制冷、形成持续的冷风响应，并在人工关闭后正常退出。

```text
人工开启制冷
→ 制冷执行建立
→ 冷风响应形成
→ 短时稳定运行
→ 人工关闭空调
→ 制冷和出风退出
```

## 2. Case范围

本Case包含：

```text
记录开启前状态
→ 开启制冷
→ 保持设置不变
→ 出风温度下降并相对稳定
→ 关闭空调
→ 制冷和出风退出
→ 关闭后观察
```

本Case不覆盖：

- AUTO控制；
- 风量阶跃；
- 温度设定阶跃；
- 内外循环切换；
- 出风模式切换；
- 除雾、除霜；
- 制热；
- 长时间热稳定；
- 保护、降额或故障注入。

座舱温度只作为辅助观察，不作为本Case完成条件。

## 3. Evidence Requirements

| ER | 名称 | 必须证明的核心事实 |
| --- | --- | --- |
| ER-01 | 开启前状态成立 | 开启前存在可识别的空调关闭状态 |
| ER-02 | 制冷请求成立 | 人工开启动作和制冷设置能够被确认 |
| ER-03 | 制冷执行建立 | 开启后系统出现区别于关闭状态的制冷执行 |
| ER-04 | 冷风响应成立 | 制冷执行后形成方向正确、可持续的冷风响应 |
| ER-05 | 短时稳定成立 | 制冷响应越过启动瞬态后能够短时保持 |
| ER-06 | 正常退出成立 | 人工关闭后，制冷和出风能够退出并保持关闭状态 |

## 4. Observable Requirements

| ER | OR | 需要观察的现象或关系 |
| --- | --- | --- |
| ER-01 | OR-01.1 | 开启前的空调关闭状态可以确认并保持 |
| ER-02 | OR-02.1 | 人工开启动作能够独立定位 |
| ER-02 | OR-02.2 | 开启后的设定温度、固定风量、风向和循环模式能够确认 |
| ER-03 | OR-03.1 | 开启前后存在可区分的制冷执行状态 |
| ER-03 | OR-03.2 | 人工请求与制冷执行响应能够分别定位 |
| ER-04 | OR-04.1 | 出风温度相对开启前状态出现方向正确的下降 |
| ER-04 | OR-04.2 | 冷风响应不是单点瞬态，而能持续观察 |
| ER-05 | OR-05.1 | 设置保持不变时存在连续的稳定制冷窗口 |
| ER-06 | OR-06.1 | 人工关闭动作能够独立定位 |
| ER-06 | OR-06.2 | 关闭后制冷和出风状态与运行状态可区分 |
| ER-06 | OR-06.3 | 关闭状态能够保持一个可观察窗口 |

OR-04.1不因现场取证条件变化而删除。有温度计时记录同一出风口温度；无温度计时记录同一出风口的人工冷热感受。手机或车机显示的温度可以作为环境或车辆状态Evidence，但必须注明来源和测量对象，不与出风口温度等同。不同取证条件均不改变正常采集流程，证据等级在采集后结合实际来源评估。

## 5. Case边界

- Case契约不绑定Vehicle、Round、DBC或具体Signal。
- 车辆静止、P挡、AUTO关闭、固定风量、固定风向、固定循环模式以及拍摄车机页面，属于本轮现场条件。
- Candidate Signal和DBC只在Case契约审核冻结后进入可观测性评估，不得反向修改ER或OR。
- 取证条件不足时采用脚本提供的可操作降级方式，不删除OR，也不自动使整个Round无效；最终完成状态由各ER的实际满足程度决定。
- Event、Acquisition Plan和VoiceRunner Script须在本契约审核通过后生成。
