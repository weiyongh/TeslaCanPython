# TM3-002～006 采集分析汇总

## 1. 汇总目的与适用范围

本文汇总 TM3-002～TM3-006 五项采集在 CAN/DBC 解析过程中遇到的问题，并区分以下四类情况：

1. 报文长度、字节布局或位定义冲突；
2. 能够解码，但缩放、枚举或物理语义尚未确认；
3. 解码结果与车辆物理状态冲突；
4. DBC 中存在定义，但当前采集域没有出现对应信号或多路复用页面。

本次使用的主用 DBC 为 `input/tesla_model3_ONYX.dbc`。CAN ID、Message 和 Signal 名称来自第三方 DBC，不等同于特斯拉官方定义。结论仅适用于本批次车辆、软件状态、接线方式和当前 CAN 采集域。

本批次包括：

- TM3-002：进入 READY 相关状态；
- TM3-003：静止挂挡；
- TM3-004：低速加速；
- TM3-005：低速松电门回收；
- TM3-006：动力电池静态基线。

## 2. 明确存在的 DBC 字节或位定义问题

| CAN ID | Signal / Message | 问题 | 当前处理 |
|---:|---|---|---|
| `0x132` | `BMS_hvBusStatus` | 实车 DLC 为 6 字节，DBC 声明为 8 字节 | 电压、电流目标字段完整位于前 6 字节，可采用允许截断方式解码；趋势可信，但保留版本差异标记 |
| `0x126` | `DI_hvBusStatus` | DBC 报文长度与实车帧不一致 | 解出的 `DI_voltage=0`、`DI_current=0`属于无效解码，完全停用；母线电压改用 `0x7AA / HVP_dcLinkVoltage` |
| `0x1D8` | `DIS_torque` | DBC 中字段重叠，强制展开后出现满量程跳变等物理不合理结果 | 不用于电机扭矩、轴速或前后电驱判断；本车为单后电机，也不将 `DIS`自动解释为前电驱 |
| `0x252` | `BMS_powerAvailable` | `BMS_hvacPowerBudget`等字段与其他字段重叠，通用解析器拒绝整帧 | 只按 DBC 位定义独立提取前 4 字节中互不重叠的最大放电功率和最大回收功率 |
| `0x1D6` | `DI_limits` | 实车报文与当前 DBC 定义不能成功匹配 | `DI_limitRegenPower`、`DI_limitRegenTorque`不能使用 |
| `0x7AA` | `HVP_debugMessage` | 实车存在 DBC 未定义的多路复用页 7 | 未知页不能套用已有页定义，只使用确认出现且字段物理一致的页面 |
| `0x7D5` | `DI_debug` | 高度依赖 `DI_debugIndex`，目标信号所在页面没有出现 | 只能解析实际出现的页面，不能跨多路复用页强制读取旋变、三相电流等字段 |
| `0x312` | BMS 热状态 | 温度字段的位定义、符号位、缩放或多路复用关系明显错误 | 因最高温度低于最低温度，整个温度结果不进入正常基线 |
| `0x212` | `BMS_minPackTemperature` | 与 `0x312`温度结果及车辆物理状态冲突 | 排除，不进入温度基线 |

### 2.1 本次形成的字节处理原则

DBC 的 DLC 与实车不同，不一定意味着整帧全部失效，应继续检查目标字段是否完整落在实车已有字节内：

- 目标字段完整位于实车字节范围内，且跨工况变化满足物理关系：可以有条件使用，并标注版本差异；
- 字段需要缺失字节、与其他字段重叠或属于未出现的多路复用页：不能使用；
- 解析器能够输出数值，不等于信号定义正确；仍须经过动作一致性、系统一致性和物理合理性验证。

## 3. 能够解码，但绝对值或语义尚未确认

### 3.1 电驱扭矩

`DI_torqueCommand`和 `DI_torqueActual`已经确认：

- 正负方向与驱动、回收工况一致；
- 请求与实际扭矩的跟随关系成立；
- 正扭矩后轴速、车速和放电电流上升；
- 负扭矩后电功率和 Pack 电流转负，车速下降。

尚未确认：

- 绝对 Nm 缩放是否完全适配当前车型软件；
- 该扭矩是电机侧、减速器输出侧，还是某种车轴等效扭矩；
- 请求与实际扭矩在同一报文中约 100 ms 一次可见，本数据不能量出逆变器内部真实控制延迟。

因此约 500 Nm 可以作为当前 DBC 下的解释值，但暂不固化为车型正常峰值。

### 3.2 功率和电流能力边界

以下 Signal 的“能力上限”角色基本成立，但绝对标定仍需在不同 SOC、温度和较高负载工况中验证：

| Signal | 本次 DBC 解释值 | 当前认识 |
|---|---:|---|
| `BMS_maxDischargeCurrent` | 约 682.624 A | BMS 最大允许放电电流，不是实际电流 |
| `BMS_maxChargeCurrent` | 约 250 A | BMS 最大允许充电/回收电流，不是实际回收电流 |
| `BMS_maxDischargePower` | 约 190.92 kW | BMS 最大允许放电功率 |
| `BMS_maxRegenPower` | 约 90.31 kW | BMS 最大允许回收/充电功率 |
| `DI_sysDrivePowerMax` | 约 248 kW | 电驱/整车当前驱动功率边界候选值 |
| `DI_sysRegenPowerMax` | 约 92 kW | 电驱/整车当前回收功率边界候选值 |

本批次实际驱动和回收负载很轻，没有接近上述上限，因此只能确认它们属于边界量，不能确认车辆是否会在相应数值处发生限扭。

### 3.3 BMS 母线电压边界

本次解码得到：

- `BMS_minBusVoltage≈106.06 V`；
- `BMS_maxBusVoltage≈201.36 V`。

它们明显不是实际 Pack/DC-link 电压，因为本次实际母线约 348 V。其可能是内部计算边界、经过不同缩放的控制参数，或者当前 DBC 不适配本车软件版本。当前名称、数值与工况不能形成物理闭环，因此不写入正常基线。

### 3.4 SOC 与能量估算

以下字段内部关系较合理，但仍属于 BMS 估算量：

- `BMS_socMin`、`BMS_socAvg`、`BMS_socUI`、`BMS_socMax`；
- `BMS_nominalFullPackEnergy=51.12 kWh`；
- `BMS_nominalEnergyRemaining=23.00 kWh`；
- `BMS_energyBuffer=2.23 kWh`。

SOC 各值之间的小差异可以解释为 BMS 内部估算分布、保护边界和 UI 显示策略。`51.12 kWh`尚未经过充放电积分或可信服务数据验证，不能仅凭单次读取直接计算 SOH。

以下字段不能使用：

- `BMS_initialFullPackEnergy=0.1 kWh`：与其他能量字段明显冲突；
- `UI_actualSOC=3%`、`UI_usableSOC=69%`：与 BMS SOC 约 46%明显冲突，`0x33A`相关定义暂不采信。

## 4. 解码结果与车辆物理状态冲突

这些冲突不能直接解释为车辆存在故障，应优先视为 DBC 版本、字段位置、有效电平、SNA 或多路复用解释问题。

| Signal | 异常表现 | 当前结论 |
|---|---|---|
| `BMS_isolationResistance` | 解码为 0 kΩ，但高压正常、接触器闭合、母线稳定且没有绝缘告警 | 不能视为真实零绝缘电阻 |
| `BMS_packTMin/BMS_packTMax` | 最高温度低于最低温度，并出现不符合电池热惯性的跳变 | 温度定义错误或页面不匹配 |
| `DI_brakePedalState` | 解码为 `INVALID`，但 `VCLEFT_brakeSwitchPressed`准确捕获制动动作 | 制动判断统一采用 `0x3C2` |
| `DI_regenLight` | 全程为 0，但负扭矩、负电功率和负 Pack 电流已经证明发生回收 | 可能是显示阈值、版本差异或定义不适用，不用于判断回收 |
| `HVP_packCurrentMia` | 解码为 1，但 Pack 电流存在且车辆正常工作 | MIA 逻辑、有效电平或页面含义待验证 |
| `HVP_gpioShuntDataReady` | 解码为 0，但缺少与分流器实际状态的独立对应 | 具体有效逻辑待验证 |
| `HVP_w001_WatchdogReset` | 每约 0.5 s 在 0/1 之间规律交替 | 更像计数或页面结构，不能解释为控制器持续复位 |
| `BMS_a084_SW_Sleep_Wake_Aborted` | 固定为 1，但车辆功能、接触器和电压均稳定 | 可能是历史/锁存状态或定义差异，不能单独判定当前故障 |

告警位为 0 只表示当前采集域没有广播对应告警，不能替代传感器、执行器和反馈链的直接验证。

## 5. DBC 有定义，但本次没有获得目标数据

### 5.1 旋变和转子位置链

本次没有解析到：

- `DI_resolverReady`；
- `DI_resolverNoCarrier`；
- `DI_resolverNoPhaseLock`；
- `DI_resolverClaMIA`；
- 旋变正弦/余弦通道偏置；
- 旋变相位偏置；
- 实时转子位置角；
- `DI_internalAngleFilt`；
- `DI_loadAngle`；
- `DI_rotorFlux`。

这并不能证明电驱系统完全不广播这些数据，只能说明当前普通运行 CAN 采集域没有出现相应的 `0x7D5`多路复用页面。

当前能够看到 `DIS_a154_resolver=0`、`PMS_w055_resolver=0`等告警结果。它们只说明没有广播相应旋变告警，不能证明旋变角度、载波、锁相和位置有效性已经被直接验证。

### 5.2 三相电流、电压与缺相状态

本次没有获得：

- U/V/W 三相电流；
- 三相相电压；
- 电流不平衡量；
- 各相功率器件状态；
- 缺相诊断的直接状态。

DBC 中存在调试页线索，但对应页面 32/38 等没有在本次采集中出现。后电驱告警矩阵 `0x356/0x35A`在正常采集中也没有出现，因此当前只能通过“请求扭矩—实际扭矩—轴速—Pack 电流”链路间接观察电驱执行状态，不能直接诊断三相缺相。

### 5.3 完整高压上电和预充过程

本批次采集开始时主接触器已经闭合，因此没有捕获：

- 预充请求；
- Pack 电压与 DC-link 电压的压差收敛；
- 预充完成状态；
- 主接触器闭合沿；
- 预充耗时。

本次建立的是“高压已经建立后的待命、READY和驱动状态链”，不是完整的高压上电基线。

## 6. 自动候选 ID 的使用边界

候选分析报告中出现了大量动作附近变化的未知 CAN ID、Byte 和 Bit。这些候选目前只能说明：

- 与事件在时间上相关；
- 某些字节或位具有重复变化；
- 可能属于请求、状态、执行反馈或系统边界。

不能仅凭自动排名直接命名。后续确认前必须排除：

- 周期计数器；
- 滚动计数器；
- CRC/校验字段；
- 多路复用索引或页面数据；
- 跨系统同步状态；
- 与目标动作同时发生、但不属于目标系统的背景变化。

候选 ID 应保留用于后续跨批次和对照实验验证，但不立即写入自建 DBC。无 DBC 情况下只记录候选角色、字节/位位置、变化方向、时间关系和置信度。

## 7. 本批次 DBC 总体可用性判断

### 7.1 可以支持本批次控制链结论

- 制动开关；
- 换挡拨杆请求和实际挡位；
- `DI_systemState`的 `STANDBY/ENABLE`状态变化；
- 加速踏板位置；
- 请求扭矩、实际扭矩和轴速；
- 车辆速度；
- 电驱实际电功率及其方向；
- Pack 电压和电流；
- BMS/HVP 接触器状态；
- HVIL 状态；
- Pack/DC-link 实际电压；
- 106 个有效 Brick 的电压、极值和压差；
- BMS SOC 主体字段。

### 7.2 角色可用，但绝对值仍需验证

- 最大充放电电流；
- 最大驱动/回收功率；
- 请求和实际扭矩的绝对 Nm 缩放；
- 标称满包能量及相关剩余能量；
- 部分电驱内部扭矩边界和温度估算量。

### 7.3 当前不能进入正常基线

- 电池最高/最低温度；
- 绝缘电阻实际值；
- `BMS_minBusVoltage/BMS_maxBusVoltage`；
- `UI_actualSOC/UI_usableSOC`；
- `BMS_initialFullPackEnergy`；
- 无物理一致性的告警和 MIA 状态位。

### 7.4 当前采集域不可见

- 旋变实时角度及直接有效性状态；
- 三相电流、三相电压和缺相直接诊断量；
- 电流环、转矩环和 FOC 内部状态；
- 完整的高压预充和接触器闭合过程。

## 8. 本批次已经形成的可靠实验闭环

尽管 DBC 存在上述问题，本批次主要实验结论没有因此失效。

### TM3-002：制动触发待命与能力释放

```text
制动开关按下
  → BMS充/放电能力边界释放
  → 电驱状态报文开始可见
  → DI_systemState进入STANDBY
```

本次没有捕获完整高压上电，也没有进入 `ENABLE`。

### TM3-003：挂挡进入可驱动状态

```text
制动按下 + D/R拨杆请求
  → 实际挡位进入D/R
  → DI_systemState进入ENABLE

P按钮请求
  → 实际挡位回P
  → DI_systemState回STANDBY
```

四次换挡闭环具有较好的重复性。

### TM3-004：低速正扭矩驱动

```text
D挡 + ENABLE + 制动释放
  → 加速踏板增加
  → 正扭矩请求建立
  → 实际扭矩跟随
  → 轴速和车速上升
  → Pack放电电流增加、电压轻微下降
```

### TM3-005：松电门自然回收

```text
D挡 + ENABLE + 车辆行驶
  → 踏板释放并越过零扭矩点
  → 请求和实际扭矩转负
  → 电驱功率转负
  → Pack电流转负
  → Pack/DC-link电压轻微抬升
  → 轴速和车速下降
```

TM3-004与TM3-005交叉确认：当前采集域内 `BMS_packCurrent>0`表示电池放电，`BMS_packCurrent<0`表示充电/回收。

### TM3-006：动力电池静态基线

本次可靠建立：

- P挡、接触器闭合、高压已建立的静态状态；
- Pack 电压约 348 V、静态放电电流约 1.1 A；
- 106 个有效串联 Brick，另有两个固定 0 V 的占位通道；
- 有效 Brick 电压约 3.284～3.286 V，压差约 2 mV；
- SOC 平均约 45.7%，UI 相关 SOC 约 46.5%；
- Pack/DC-link 电压接近，12 V 母线约 13.0～13.1 V。

温度、绝缘和两个 BMS 母线电压边界字段因物理冲突被排除。

## 9. 对控制树和诊断树的总体增量

```text
高压已经建立
  ├─ Pack接触器闭合
  ├─ HVIL正常
  └─ Pack电压≈DC-link电压
      ↓
制动开关确认
  ├─ BMS充/放电能力释放
  └─ 电驱进入STANDBY
      ↓
D/R请求被接受
  └─ 实际挡位进入D/R
      └─ 电驱进入ENABLE
          ├─ 正扭矩请求
          │   └─ 实际扭矩→轴速/车速上升→电池放电
          └─ 负扭矩请求
              └─ 实际负扭矩→负电功率/负Pack电流→车辆减速
```

当车辆出现无法驱动、驱动无力或回收异常时，可按以下顺序定位断链：

```text
接触器/HVIL/DC-link是否成立？
  → BMS能力边界是否被压低？
  → 制动、挡位和驱动许可是否成立？
  → 是否生成扭矩请求？
  → 实际扭矩是否跟随？
  → 轴速、车速和Pack电流是否响应？
  → 是否存在旋变、功率级、缺相或稳定控制告警？
```

## 10. 最小下一步验证

1. 在维护模式下重复正常状态采集，检查是否新增 `0x7D5`旋变页、三相电流页和后电驱告警矩阵；
2. 使用车辆服务界面或可信诊断数据同步记录电池温度和绝缘值，校正当前 DBC；
3. 单独采集完整的休眠唤醒、高压预充、接触器闭合以及下电母线下降过程；
4. 在不同 SOC、温度和负载下交叉验证最大充放电电流/功率边界及扭矩绝对缩放；
5. 使用充放电能量积分或可信服务数据验证 `BMS_nominalFullPackEnergy`，再用于 SOH 趋势；
6. 对未知 ID 采用单变量、可重复的对照实验，只在跨样本一致后提升证据等级。

## 11. 总结结论

本批次 DBC 虽然存在报文长度差异、字段重叠、多路复用页缺失、缩放待验证和部分物理冲突，但没有破坏主要实验闭环。

已经能够可靠描述：

- 高压已建立后的待命状态；
- 制动、挂挡与 `STANDBY/ENABLE`状态变化；
- 正扭矩驱动闭环；
- 负扭矩能量回收闭环；
- 动力电池静态电压、电流、SOC与 106 个有效 Brick 的一致性。

当前未确认项主要集中在：

- 电驱内部调试量；
- 旋变和三相电流/电压的直接状态；
- 温度、绝缘及部分告警定义；
- 扭矩与能力边界的绝对标定；
- 未知候选 ID 的具体语义。

因此，当前第三方 DBC 适合辅助建立诊断控制链和相对变化基线，但不能未经验证直接作为全部信号的官方定义或绝对正常阈值。
