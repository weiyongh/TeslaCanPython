# 采集数据校验识别代码设计

## 目标

用一个小型Python工具完成确定性读取、审核文档生成和审核后JSON回写。AI负责识别图文和语音语义，不把AI能力硬编码进共享程序。

```text
Acquisition Package
→ prepare生成acquisition_context_toreview.json
→ AI补充识别值并生成Review Markdown
→ 人工在Markdown中审核
→ finalize回写acquisition_context.json
```

## 程序文件

```text
src/tooling/acquisition_context.py
tests/tooling/test_acquisition_context.py
doc/tools/acquisition_context/README.md
```

- `acquisition_context.py`：提供`prepare`、`render-review`和`finalize`三个小命令；第一版保持单文件，不拆包。
- `test_acquisition_context.py`：验证输入读取、Review渲染、审核门和JSON回写。
- `README.md`：只写命令、输入输出路径和审核方法。

不新增数据库、Web服务、审核UI、独立Schema文件或工作流引擎。

### `src/tooling/acquisition_context.py`

这是唯一业务程序，具体实现以下功能：

| 函数 | 作用 |
|---|---|
| `inspect_package(package_dir)` | 检查必要输入、找到唯一Vehicle Marker并列出照片、Note、录音和ASC文件。 |
| `read_voicerunner(package_dir)` | 读取`session.json`和`event_timeline.csv`，形成Case、Round、Event及Resource关联。 |
| `read_asc_time_info(asc_path)` | 只读取ASC文件的基本起止与时长，不解析CAN帧内容。 |
| `build_review_context(...)` | 将Validation结果和`Round → Event → Resource`整理为待审采集上下文。 |
| `write_toreview_json(context, output_path)` | 持久化`acquisition_context_toreview.json`，供AI识别和后续审核使用。 |
| `render_review_markdown(context, output_path)` | 从待审上下文生成`recog_values_review.md`，包含中文采集名、图片预览和Value审核表。 |
| `parse_review_markdown(review_path)` | 读取人工修改后的表格，恢复Event、Resource、Value及审核结论。 |
| `validate_approved_review(review)` | 检查整体`APPROVED`、无`PENDING`、ID唯一且来源仍存在。 |
| `write_context_json(toreview, review, output_path)` | 合并待审上下文与审核结果，原子写入正式`acquisition_context.json`。 |
| `main()` | 解析`prepare / render-review / finalize`命令并输出结果摘要或错误。 |

AI识别不是该程序内部算法。`prepare`先持久化确定性采集上下文；当前AI工作过程读取其中的Resource，补充AI识别值和位置，再生成Markdown审核界面。程序负责确定性解析、承载、检查和回写。

### `tests/tooling/test_acquisition_context.py`

这是自动测试程序，不处理正式数据。它使用临时目录构造最小采集包，具体验证：

- Vehicle Marker、VoiceRunner JSON/CSV、Event和Resource关联能够正确读取；
- 多ASC只提取文件级时间信息，不进入CAN Payload分析；
- 待审JSON能够避免后续步骤反复解析原始采集包；
- Review包含中文采集名、`![img](url)`和多Value表格；
- `PENDING`、重复ID、来源缺失或未`APPROVED`时拒绝回写；
- `ACCEPTED / CORRECTED / REJECTED / HUMAN_ADDED`能够无歧义写入JSON；
- S0009集成测试得到预期的Event、照片和ASC数量。

## 输入输出

输入：一个Acquisition Package目录，包含Vehicle Marker、`session.json`、`event_timeline.csv`、照片、Note、录音和ASC实际文件。

输出固定为：

```text
output/acquisition_context/<Acquisition Package目录名>/acquisition_context_toreview.json
output/acquisition_context/<Acquisition Package目录名>/recog_values_review.md
output/acquisition_context/<Acquisition Package目录名>/acquisition_context.json
```

`acquisition_context_toreview.json`保存Validation结果、采集身份、Event、Resource、文件和基本时间信息，以及AI后续补充的原始识别值。它是可重复使用的待审中间数据，不是Analysis正式输入。

`recog_values_review.md`显示采集中文名、原始目录名、Validation摘要及`Round → Event → Resource → Value`。图片使用`![img](url)`预览。每个Value保留稳定`Value ID`、来源位置、AI原始值、人工确认值、单位、审核状态和备注。

`acquisition_context.json`只在Review整体状态为`APPROVED`且没有`PENDING` Value时生成。

## 核心处理

### `prepare`

1. 确认目录和必要文件可读，读取唯一Vehicle Marker。
2. 读取VoiceRunner JSON/CSV，提取Case、Round、Event及Resource关联。
3. 只读取ASC文件级起止和时长信息，不解析CAN Payload。
4. 按目录名/脚本名提取采集中文名。
5. 持久化`acquisition_context_toreview.json`，后续步骤不重复解析原始采集包。
6. AI查看图片、Note和录音转写，在待审上下文的对应Resource中增加Value；不改变确定性身份和关联。
7. 从待审上下文生成按Event和Resource排列的Review Markdown。

Validation只输出`PASS / WARNING / FAIL`。同版本日常Round不做深度合同审计。

### 人工审核

人工保留`AI识别值`和`值位置`，修改`人工确认值 / 审核状态 / 审核备注`，也可增加`HUMAN_ADDED`行。不同Resource的值分别保留，不平均、不覆盖。

### `finalize`

1. 读取`acquisition_context_toreview.json`，并核对原始文件路径、大小和修改时间未变化。
2. 解析Review中的Round、Event、Resource和Value ID。
3. 拒绝整体状态非`APPROVED`、仍有`PENDING`、ID重复或来源文件不存在的文档。
4. 按人工审核状态写入JSON：`ACCEPTED / CORRECTED / HUMAN_ADDED`保留，`REJECTED`保留记录但不作为有效值。
5. 使用临时文件完成写入后替换目标文件，避免产生半份JSON。

待审JSON是处理快照，Markdown是人工审核界面，正式JSON是Analysis机器输入；三者职责不同，不形成并行真值，正式JSON不再反向覆盖Review。

## 命令形式

```sh
python3 src/tooling/acquisition_context.py prepare <Acquisition Package目录>

python3 src/tooling/acquisition_context.py render-review \
  <acquisition_context_toreview.json>

python3 src/tooling/acquisition_context.py finalize \
  <acquisition_context_toreview.json> \
  <recog_values_review.md>
```

成功输出生成文件路径和Event、Resource、Value数量；失败返回非零状态和明确原因。

## 结果验收

使用S0009验证以下结果即可：

- 正确识别`L3-Charge-Slow-FullCycle / 慢充全过程采集 / TESLA-M3-SOP5 / S0009`；
- 形成11个Event、9张照片、无Note、录音关闭及两个ASC的基本信息；
- Review中图片可直接预览，一个Resource可列多个Value；
- `PENDING`不能回写，`APPROVED`可以生成JSON；
- JSON保留AI原始值、人工确认值、来源位置和审核状态；
- 全过程不读取CAN Payload，不产生Analysis结果。
