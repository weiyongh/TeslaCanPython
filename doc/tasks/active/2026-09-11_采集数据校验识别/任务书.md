# 采集数据校验识别任务书

> 目标：建立实车原始采集包（Acquisition Package）进入CAN分析前的通用校验（Validation）和采集信息识别（Recognition），使每次采集能够快速确认输入并识别现场事实。
>
> 本任务到Recognition结果为止，不进入分析（Analysis）。

## 1. 背景与依据

实车采集结果包含车型标记（Vehicle Marker）、VoiceRunner输出、现场图片、Note、录音以及一个或多个ASC。以后处理不同Case和车型时，应沿用同一套Validation和Recognition方法，不再每次重新搜索文档、讨论输入关系或临时判断ASC归属。

- `android/CANVoiceRunner/doc/V2优化/任务7/event_timeline_csv_v1_接口合同.md`

## 2. 本次任务

### Validation / 原始采集包校验

- 确认必要输入存在且可读。
- 读取唯一的Vehicle Marker。
- 确认VoiceRunner的`session.json`和`event_timeline.csv`属于同一次采集。
- 提取VoiceRunner与ASC的基本时间信息。
- VoiceRunner同版本且输入合同已经验证通过后，日常Round不重复进行深度一致性审计；仅在首次接入、版本/合同变化或出现明确异常时提高校验深度。

### Recognition / 采集信息识别与Event关联

- 识别Case、Vehicle和Round。
- 读取Event的实际时间、状态、标题和说明。
- 按`session.json`已有ID关系整理Event关联的照片和Note。
- 登记本次录音及其状态。
- 识别图片、Note和录音中可见、可读或可听的现场信息。
- 形成供后续Analysis使用的采集事实。

## 3. 输出物

每个Acquisition Package经解析和Validation后，先持久化待审上下文：

```text
acquisition_context_toreview.json
```

它保存采集身份、Validation结果、Event、Resource、基本时间信息和AI原始识别值，避免后续步骤反复解析原始采集包；它不是Analysis的正式输入。

随后生成中间审核文档：

```text
recog_values_review.md
```

它按Event和Resource列出图片、Note、录音转写及AI识别值，供人工查看、校对和补充。审核通过后，将审核结果写入正式输出：

```text
acquisition_context.json
```

它是Validation和Recognition共同形成的采集上下文（Acquisition Context），作为后续Analysis的输入。核心结构为：

```text
Validation
Round（1）
└── Event（1...N）
    └── Resource（1...N）
        └── Value（0...N）
```

- `validation`保存输入可读状态、Vehicle Marker、VoiceRunner与ASC基本时间信息，以及是否出现需要提高校验深度的明确异常。
- 每张图片、每条Note或每个录音片段分别作为一个Resource；一个Event可以有多个Resource。
- 一个Resource可以包含多个Value。
- Value保存AI原始识别值、人工确认值和审核状态，可由人工直接编辑。
- 不同Resource中的实际值分别保留，不平均、不覆盖差异。

`recog_values_review.md`只是`acquisition_context.json`形成前的可读审核视图，不建立第二套数据真值；审核后的JSON是后续Analysis使用的正式输出。运行时可以在终端打印简短摘要，不另行生成Validation报告或其他Recognition报告。输出不复制照片、录音或ASC，不包含CAN、Signal或诊断分析结果。

## 4. 边界

本任务不读取或分析CAN报文Payload，不进行ASC报文解析、DBC解码、CAN ID分析、Signal统计、控制关系推理、Evidence Plan、Evidence Assessment或诊断结论，也不建设采集管理平台。
