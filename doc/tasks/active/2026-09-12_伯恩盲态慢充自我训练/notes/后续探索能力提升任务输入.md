# 后续探索能力提升任务输入

> 来源：S0009伯恩盲态慢充自我训练的评分后复盘  
> 状态：MEMO / NOT_STARTED  
> 用途：作为后续独立Task的输入，提升无精确地图条件下的CAN探索能力。  
> 当前决定：不设计、不生成、不启动新的实车采集计划。

## 1. 核心问题

本轮能够根据Event和ASC变化找到充电主相关区域，但还不能稳定判断一个命中位置究竟是独立field，还是连续量/枚举field内部的随动bit。

下一阶段的重点不是扩大候选数量，而是提高field边界和数据形态识别能力。

## 2. 应优先消除的误判

### 2.1 连续量内部bit被误判为状态开关

- 检查相邻bit的进位关系和变化频率梯度。
- 比较组合后的8/10/12/14/16-bit值是否比单bit更连续。
- 某bit若只在组合值跨阈值时翻转，降低其独立状态概率。
- 同一byte多个bit同时命中时，先假设它们属于一个整体field。

### 2.2 枚举field被拆成多个独立状态

- 对相邻bit构建联合取值序列。
- 统计实际组合值及重复状态迁移路径。
- 优先输出“多bit阶段候选”，而不是多个单bit Signal。
- 仅当某bit能够跨场景独立变化时，才拆成布尔量。

### 2.3 共同响应者被误认为目标控制链成员

共同原因可能是网络唤醒、低压变化、高压母线、驻车状态、热管理或ECU初始化。

后续应使用历史ASC作为负对照，优先检查候选在非充电唤醒、行车高压、空调负载、驻车解锁等场景是否同样变化。

### 2.4 对称或同步报文形成伪独立证据

- 检查成对报文是否长期结构对称。
- 比较周期、Counter、Checksum与非目标场景行为。
- 不将同源镜像报文当成两份独立证据。

### 2.5 功能角色声明过宽

每个候选必须回答：

1. 在什么条件下建立？
2. 在什么条件下解除？
3. 与上下游候选的时序关系是什么？
4. 哪个反事实场景能够推翻当前解释？

## 3. 后续侦察管线

    报文行为
    → field结构
    → 数据形态
    → 状态与时序
    → 跨场景反证
    → L3角色投射

不得再从“事件相关bit”直接跳到L3角色。

### 3.1 field数据形态分类

每个候选先估计以下类别：

- 独立布尔量；
- 枚举状态；
- 连续量；
- Counter；
- Checksum；
- MUX/条件field；
- 未知结构。

只有独立布尔概率足够高时，才允许输出单bit状态声明。

### 3.2 拆分三类置信度

    位置相关置信度
    field边界置信度
    功能角色置信度

“很可能位于目标矿区”不等于已经画准field边界，也不等于确认了功能角色。

## 4. 历史ASC的使用原则

历史ASC是既有实验产生的反事实工具。引入每份历史ASC前先说明：

- 它改变了哪个条件；
- 它能排除哪个竞争解释；
- 它与当前Vehicle/Round的适用边界；
- 候选在该场景中应该如何表现；
- 实测结果是支持、反驳还是仍无法区分。

## 5. 未来实验方向备忘（当前不启动）

### 5.1 接口状态分离组

    关盖未连接
    → 开盖不插枪
    → 插枪不启动
    → 解锁但不拔枪
    → 再锁止
    → 拔枪
    → 关盖

用于分离充电口门、物理连接、锁止、解锁允许、连接装置属性和网络唤醒。

### 5.2 会话与功率分离组

    保持插枪未充电
    → 启动
    → 功率稳定
    → 改变电流限额
    → 再次稳定
    → 停止但保持插枪
    → 重新启动
    → 再次停止

改变电流限额可以制造多级连续变化，用来暴露伪装成布尔状态的连续量内部bit。

## 6. 后续Task验收方向

- 减少同步变化量被提交为独立点位的数量。
- 提高field边界命中率。
- 在输出前识别连续量内部bit与枚举field内部bit。
- 使用负对照主动删除共同响应者。
- 输出可证伪的建立条件、解除条件和上下游时序。
- 不用扩大点位数量掩盖边界不确定性。
