# HVAC Round 4 第5次预审整改意见

## 一、预审结论

当前提交的文件、状态、Evidence索引、方法合同、数量闭合和归档指纹已经满足前序整改要求，但正式报告仍有部分表述超过现有Evidence能够支持的范围。

本次预审结论：

`PREAUDIT_REWORK_REQUIRED`

当前状态保持：

`REVISED / PENDING_RE-AUDIT`

## 二、已经成立的结论边界

以下内容可以保留：

1. 五个Session均记录E01至E13，且各有一个覆盖六个稳态窗口的数据段。
2. 正式产物中的Session数、Event数、照片数、帧数、候选组数、raw bit数、分类数和转换记录数相互一致。
3. 23个既有raw bit在五轮六状态下形成9/5/8/1的实验相关分类。
4. 93个全总线补充结果是raw bit observations，不是93个Signal或93条独立Evidence。
5. 风量只有2和6两个水平，不足以恢复完整编码、位宽、比例或实际风机量。
6. A/C切换相关观察不能证明压缩机运行或实际制冷建立。
7. 当前时间对齐精度不支持控制器级亚秒排序。
8. S0023补拍处置继续按已放行结论保留。

## 三、必须整改的问题

### 1. “不同刺激拆开组内成员”不能直接证明它们不是单一字段

`README.md` 当前写道：

> 组内成员被不同激励拆开，直接证明Round 3的“同字节组”不能当作单一字段。

组内bit在不同状态转换中呈现不同变化，只能证明原有掩码不是一个具有单一刺激响应模式的整体。多bit编码中的不同bit也可能在不同取值转换中分别变化，因此现有Evidence不能直接推出真实字段边界。

整改要求：

- 删除“直接证明不能当作单一字段”的结论；
- 改为描述本轮实际观察到的组内响应分化；
- 明确原有分组假设受到挑战或需要重新评估，但不宣称真实字段边界已经确定；
- 同步检查报告标题及其他位置是否把本轮结果提前表述为字段已经完成解耦。

### 2. “制冷链相关”超过当前Evidence层级

当前Evidence直接支持的是raw observation与A/C UI切换在本实验状态序列中的可重复关联。没有独立Evidence证明这些观察属于制冷请求、许可、执行或物理制冷链。

整改要求：

- 将“A/C UI状态或制冷链相关”收窄为“与本轮A/C UI切换相关”；
- 分类名称在首次出现时明确为实验刺激标签，不是系统语义命名；
- 不使用“制冷链相关”概括尚未确定的控制层级。

### 3. “无解析失败”不能写成“无帧缺损”

现有正式Evidence记录了：

- 形似数据行但无法解析的记录数为0；
- 段内时间戳倒退数为0；
- 每个Session的首末时间和总帧数。

这些事实不能单独证明采集过程中没有丢帧或时间间隙。

整改要求可选择以下一种方式：

1. 将 `README.md` 和 `VALIDATION.md` 中“无可解析帧缺损”等表述收窄为“未发现无法解析的数据样式行，未发现段内时间戳倒退”；或者
2. 补充明确的帧间隔检查口径和结果，再按照实际Evidence描述间隙情况。

不得把“无法解析记录为0”解释为“丢帧为0”。

### 4. 首末时间覆盖不能单独证明记录连续

`VALIDATION.md` 当前根据文件覆盖首末时间写成“CAN文件连续覆盖完整”。只有首帧、末帧、单段和无时间戳倒退，仍不足以排除段内较长时间间隙。

整改要求可选择以下一种方式：

1. 删除“连续覆盖完整”，改为“文件首末时间覆盖六个稳态窗口”；或者
2. 提交段内时间间隙统计及明确判定口径，再根据实际结果使用“连续”表述。

### 5. 人读报告中的时间偏移精度超过时间基准能力

`README.md` 将事件对齐偏移显示到毫秒级，并使用“响应”“晚于”等容易被理解为实际因果延迟的措辞；但 `METHOD.md` 已明确文件头墙钟只有整秒精度。

整改要求：

- 将这些数值明确称为“重建时间轴上的对齐偏移估计”，不是控制响应延迟；
- 人读报告按时间基准能力收敛显示精度；
- 负偏移只表述为落在对齐不确定范围内，不解释为事件前响应；
- 不根据这些偏移确定请求、许可、执行或反馈顺序；
- 机器明细可保留原始计算精度。

### 6. “五轮同条件重复”需要收窄适用范围

当前正式Evidence能够确认五轮使用相同的UI状态序列和采集设计，并记录了画面中的温度显示；没有完整记录所有可能影响系统行为的车辆和环境条件。

整改要求：

- 将“五轮同条件重复”收窄为“相同采集设计和UI状态序列下的五轮重复”；
- 不把未记录条件默认为五轮完全一致；
- 保留跨环境、车辆状态和软件版本不可外推的边界。

## 四、同步要求

完成上述修改后：

1. 更新 `README.md` 和 `VALIDATION.md`；
2. 如术语或方法边界发生对应变化，同步更新 `METHOD.md`；
3. 更新 `SELF_REVIEW.md`，逐项检查事实、相关性、语义、执行和物理结果之间是否发生跨层推断；
4. 更新 `REWORK_RESPONSE.md`，记录每项表述的修改位置及是否影响机器结果；
5. 更新 `archive_manifest.md` 中受影响文件的SHA-256；
6. 机器产物没有实际错误时，不得为了文字整改改变机器统计结果。
