# Bourne Round 4 — M Audit

## 一、审计边界

本次只评价 Round 4 正式提交中的数据、方法、Evidence 和结论，不使用当前提交之外的既有答案判断结果。

本次核验范围为 `results/round_4/` 中由 `archive_manifest.md` 冻结的 16 项正式提交物，以及 `results/README.md` 对该提交的正式入口记录。未检查分析程序、探索过程或临时产物。

## 二、核验通过的事实

1. 归档清单所列 15 个非自引用文件的 SHA-256 均与当前文件一致。
2. 数量闭合：5 个 Session、65 个 Event、31 张照片索引、5 个数据段、3,711,471 帧、80 行组状态明细、16 行组汇总、23 行既有 raw bit 拆分、400 行转换记录、93 行全总线补充观察。
3. 各表主键唯一；每个 Session 均有 13 个 Event；Event 关联照片数合计 31，与照片索引一致。
4. `timeline_reconstruction.json` 中六个稳态窗口可由 `event_evidence_index.csv` 的实际 Event 时间和 `METHOD.md` 规定的保护区逐项复算。
5. 23 个既有 raw bit 的结果闭合为 9 个 HVAC/送风开启相关、5 个风量变化敏感、8 个 A/C UI 切换可逆相关、1 个本轮保持常值且未分类；五轮一致性和最低窗口纯度与机器表一致。
6. 16 个既有组中 15 个满足各自已定义的组级模式，1 个本轮保持常值；逐 Session 组轨迹与组汇总一致。
7. 93 个全总线结果均明确以 raw bit observation 计数，没有被写成 93 个字段、Signal 或独立 Evidence。
8. 报告已把 UI 设置事实、raw 值相关性、执行器实际运行和物理制冷结果分开；时间偏移也被限制为整秒级对齐估计，没有被写成控制响应延迟。

## 三、发现的问题

### 1. 多状态实验尚未形成可审核的 field-level hypothesis

当前正式结论的基本单位仍是 raw bit 的六状态刺激响应分类。`round3_group_summary.csv` 保存的是继承自 Round 3 的字节加掩码分组，并未提交本轮形成的字段边界假设、候选分区、竞争解释及逐项存废裁决。

报告确认部分旧组的组内成员出现不同刺激响应，这足以说明旧分组需要重新评估；但当前提交只停在“需要重新评估”，没有完成重新评估本身。对于组内成员保持同步或互补的其他旧组，也没有说明现有数据究竟支持保留一个多 bit 字段假设、拆成若干单 bit 假设，还是只能维持未决。

因此，本轮确实提高了 raw-bit stimulus classification 的分辨率，也否定或削弱了部分旧分组；但尚未把多状态 Evidence 定型为 field-level hypothesis。

### 2. 组级单标签不能完整表达复合响应组

组级分类规则按某一对状态差异接受分类，但没有要求该组在其他刺激维度上保持不变。对于已经由 bit 拆分表证明包含不同响应成员的组，`classification_accepted=True` 和单一 `classification` 不能表示整个组具有单一刺激响应。

README 对这种分化作了文字提示，但机器汇总仍把这些组计入单一类别，导致“15 组接受分类”和 5/5/5 的组级计数容易被理解为 15 个内部一致的单类组。人读结论与机器状态没有完全闭合。

### 3. 照片集合指纹不能按提交中声明的规则独立复算

`input_evidence_manifest.csv` 声明照片集合指纹是对按文件名排序的 `filename  file_sha256\n` 记录计算 SHA-256。使用 `photo_evidence_index.csv` 中逐张登记的文件名和 SHA-256 按该规则复算，五个 Session 均不能得到清单登记的集合指纹。

逐张照片指纹本身格式完整，照片数量和 Event 关联也闭合；问题在于集合指纹的生成口径或登记值未定型，当前 provenance 链不能按其书面合同复现。

### 4. 正式状态自审存在矛盾

Round 4 各主要状态文件现记为 `PREAUDIT_PASSED`，但 `SELF_REVIEW.md` 的“状态一致”Evidence 仍称正式文档均为 `REVISED / PENDING_RE-AUDIT`。该 PASS 声明与实际文件不符。

此外，正式入口 `results/README.md` 仍称 Round 4 只完成较早一次整改并处于 `REVISED / PENDING_RE-AUDIT`，与 Round 4 当前正式状态冲突。

## 四、当前最准确的结论边界

Round 4 已可靠证明：在五次采用相同采集设计和 UI 状态序列的 Session 中，23 个既有 raw bit 可以按六个稳态窗口区分为三类可重复刺激响应和一项本轮常值观察；部分旧字节掩码组的内部成员表现出响应分化；另有 93 个全总线 raw bit observations 满足相同的五轮稳态门槛。

当前 Evidence 不能把这些计数解释为字段数、Signal 数或独立 Evidence 数，也不能确认设置以外的请求、许可、执行、反馈或物理制冷层级。

就分析层级而言，本轮结论停留在 raw-bit stimulus classification，以及对既有字段分组假设的局部反证；尚未形成完整、可审核的 field-level hypothesis 集合。

## 五、当前 Round 整改要求

1. 仅使用现有 Round 4 数据，对每个继承的字段组给出本轮存废状态，并提交字段级假设表。至少记录候选边界或分区、六状态取值、组内成员是否同响应、仍相容的竞争解释、支持或否定依据及 Evidence Boundary。
2. 重新定义组级分类接受条件，使单类组、复合响应组、保持常值组和证据不足组在机器产物中可被明确区分；同步修正组级数量和 README 表述。不得把同步 raw bit 自动合并成一个字段。
3. 定型照片集合指纹的唯一生成规则，并使五个集合指纹可由正式逐张索引复算；如登记值或规则变化，同步更新相关 provenance 记录。
4. 修正 `SELF_REVIEW.md` 中与实际状态不符的 PASS 依据，并使 `results/README.md`、Round 4 状态文件和归档清单保持一致。
5. 更新受影响文件的 SHA-256 与归档清单，并在整改答复中说明哪些机器结果和组级计数发生变化。

## 六、整改后仍可能存在的 Evidence Gap

即使完成上述整改，现有多状态数据仍可能无法唯一确定某些同步或互补 raw bit 是同一字段、多个独立状态、枚举组成位、复制值或派生值。无法唯一裁决时，应保留多个竞争假设并说明现有数据为何不能区分，不得用单一命名替代不确定性。

现有照片只覆盖 UI 可见事实，当前提交仍不能据此确认执行器实际运行、物理制冷建立或内部控制层级。
