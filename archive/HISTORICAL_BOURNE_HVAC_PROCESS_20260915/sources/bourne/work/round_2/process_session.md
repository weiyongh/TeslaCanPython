# 第二轮过程归档

## 范围与目标

- 处理对象：Workspace 内已有 HVAC 与交流慢充结构化采集。
- 目标：复核第一轮零候选结论，重建跨 ASC 分段的统一脚本时间轴，并重新筛选状态候选。
- 边界：本轮未执行新实车采集，正式分析结果统一存放于 `results/round_2/`。

## 问题发现

检查 HVAC 与慢充采集时发现，两组数据都不是单一连续 ASC，而是由多个 ASC 分段组成。每个新分段内部的 ASC 相对时间戳重新从零开始。第一轮把各分段当作独立完整时间轴，因而没有把后段中的关键关闭、停止或拔枪状态正确映射回脚本时间。

## 时间轴重建方法

1. 读取每个 ASC 文件头记录的墙钟起始时间。
2. 读取对应 `session.json` 中的 `session.start_clock`。
3. 以两者的墙钟差计算该 ASC 分段相对脚本零点的偏移。
4. 将分段内每帧相对时间加上该偏移，转换为统一脚本时间。
5. 对重叠、间隙、总帧数和关键事件窗口进行核验，避免再次把分段零点误当作会话零点。

重建后的覆盖情况：

- HVAC：主段覆盖脚本 0.107–444.121 s，第二段覆盖 444.107–659.716 s；两段约重叠 0.014 s。
- 交流慢充：主段覆盖脚本 −0.858–441.514 s，第二段覆盖 442.142–539.680 s；两段约有 0.628 s 无帧，未覆盖主要状态窗口。

## 双对照筛选

候选筛选同时使用动作前与动作后对照，而不是只比较单侧状态：

- HVAC：要求候选在“OFF 前”与“OFF 后”一致，并与中间“ON”稳态区分；同时核对全程翻转次数与开启、关闭事件的同步性。
- 交流慢充：要求 Charging 候选与“未插枪”和“插枪等待”同时区分，并在正常停止、拔枪后的非充电状态退出；对停止阶段抖动候选降低优先级。

验证汇总记录为：HVAC 双对照共同 bit 候选 32 个，慢充 Charging 双对照共同 bit 候选 181 个。优先候选及其窗口纯度、建立和退出时刻见正式结果。

## 对第一轮结论的修正

第一轮“HVAC 和交流慢充没有严格二态候选”的零候选结论撤回。零结果的原因是 ASC 分段时间戳重置后未被拼接，不是车辆总线上不存在候选。第二轮只把结果表述为未知总线候选，不将其直接命名为已确认 DBC 信号。

## 本轮结论与限制

- 重建后的单周期数据中，HVAC 存在与 OFF/ON/OFF 高度同步的优先候选。
- 慢充存在能够区别未插枪、插枪等待、充电稳态与停止后状态的优先候选。
- 当前仍只有单周期证据，尚不能完成跨轮次复现，也不能仅凭同步性确定 Request、Condition、Action、Feedback 的语义层级。
- 正式结果位于 `results/round_2/`；本文件只归档过程与决策，不复制候选表作为新的结果来源。

## 后续现场方案决策

慢充现场验证最终改为三次独立单轮采集。每轮均独立完成“未连接→插枪→扫码启动→确认充电→正常停止且保持插枪→安全拔枪→未连接稳态”，不在一个长会话内连续重复三轮。单轮脚本为 `experiment_vault/scripts/L3-Charge-Slow-MinSingRound_单人最低负担慢充单轮采集脚本.txt`。

这样可分别保留每轮原始文件、事件时间轴与照片证据，并直接检验候选的跨轮次复现性。每轮由 VoiceRunner 自动打点；正常零备注，仅异常说明备注。
