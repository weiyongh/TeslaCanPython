# 第三轮处理过程：HVAC 五轮复现

## 任务与保护原则

用户要求开始分析新采集的五份 HVAC 数据，同时保留上轮有效输出并文档化两轮差异和结论理由。因此本轮新建 `results/round_3/`、`work/round_3/` 和独立分析脚本，没有用第二轮脚本覆盖旧 CSV/JSON。收到 M 纯审计后，在当前 Round 内继续返工。

## 输入确认

目标目录实际为 `evidence_vault/historical_cases`。识别出 S0014–S0018 五个名称含 `L3-HVAC-Cooling-MinSingRound` 的会话。每个会话包含一个 ASC、`session.json`、事件 CSV 和三张照片。

## 方法选择理由

第二轮的价值在于修复多段 ASC 的时间轴错误，并提出五个单周期优先候选；其不足是没有跨会话重复证据。本轮没有把五个会话简单拼成一个总体样本，因为总体纯度可能掩盖单轮失败。筛选逻辑改为先在每轮内部判定，再做五轮交集。

每轮稳态窗口按实际事件时间计算：OFF 前为 E02+5 s 至 E03−5 s，ON 为 E04 至 E05−5 s，OFF 后为 E06 至 E07−5 s。这样避开 UI 操作和系统响应瞬态，又使用 E04/E06 的现场确认作为稳态起点。

## 执行步骤

1. 读取每个 `session.json`，检查完成状态、事件和实际触发时间。
2. 用 ASC 头部墙钟与 `session.start_clock` 建立脚本时间；记录每段帧数、覆盖范围、无效行和倒退时间戳。
3. 对全部 CAN ID、字节和 bit 统计逐轮三个稳态窗口的模态值、纯度和样本数。
4. 保留每轮 OFF 前＝OFF 后≠ON、最低纯度 ≥95%，且五轮方向一致的字段。
5. 对通过者再次扫描完整会话，记录开启/关闭附近的转换、相对事件延迟和全程翻转次数。
6. 以“每轮恰好两次翻转、两次事件附近均找到转换且方向符合稳态模式”定义跨五轮复现的二态 raw bit。
7. 单独对照第二轮五个优先候选，避免新一轮全量排序冲淡历史主线。
8. 人工查看五轮 E03/E05 照片，确认 UI 状态与事件标签一致。

## 中间结果与收敛

- 输入 5 个会话、2,592,668 帧，未发现 CAN 时间轴倒退或可解析帧缺损。
- 52 个 bit 通过五轮稳态一致性门槛。
- 其中 23 个进一步通过全程两次翻转与方向门槛；另外 29 个虽稳态相关，但存在多次翻转、事件转换缺失或较低纯度，保留在完整候选表中而不列入二态复现集合。
- 第二轮五个优先候选均为 5/5、最低纯度 100%、每轮两次翻转，因此上轮核心结论没有被推翻，而是得到五个同条件会话的重复支持。

## 审计后返工

- 将“强候选”统一改称“跨五轮复现的二态 raw bit”。
- 转换匹配由“事件附近最近翻转”改为“事件附近且 before→after 与稳态方向一致的最近翻转”。
- 新增 `raw_field_groups.csv`，将23个 raw bit 收敛为16个字节级待恢复字段组，并标记完整字节是否重复、同组成员是否精确同步。
- 删除未定义的C+/B评级，改用直接证据描述。
- 亚秒时延只保留为审计明细，不用于近事件组排序；报告只陈述近事件与数秒后两个层级。
- 将“五次独立实验”改为“五个单独采集会话中的同条件重复验证”。
- 在正式报告中分开陈述已证明事实与尚不能确定的竞争解释，并暂停下一轮采集计划。

## 结论边界

五轮采用相同脚本和近似相同环境，所以能够证明“相同工况重复性”，不能证明跨温度、SOC、风量或车辆的普适性。多个 bit 同步变化也不等于多个独立物理信号。当前数据只有总体 OFF/ON 两类主要状态，且缺少与实际执行同步的外部事实，因此仍无法区分布尔位、枚举组成位、连续量阈值位、请求状态、派生状态或实际执行反馈；具体语义仍未确认。

Round 3 已通过最终 M Re-Audit，正式状态为 `CLOSED`；本轮停止在现有数据的事实、限制和 Evidence Gap。
