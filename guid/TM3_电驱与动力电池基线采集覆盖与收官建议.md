# Tesla Model 3 电驱与动力电池基线采集覆盖与收官建议

> 用途：记录当前 TeslaCanPython
> 基线采集阶段的覆盖判断、建议补充项，以及后续 Baseline Coverage Matrix
> 与阶段收官原则。\
> 当前状态：除交流慢充（TM3-016）外，已完成多项围绕电驱与动力电池的正常基线采集；TM3-007、TM3-008
> 已用于固化 Golden 分析架构。

## 1. 当前阶段判断

目前围绕电驱与动力电池已经覆盖了多个重要的正常状态与动态过程，包括：

-   静态基线；
-   进入 READY；
-   静止挂挡；
-   低速加速；
-   低速松电门回收；
-   中等负载加速；
-   制动协调；
-   驾驶模式扭矩对比；
-   电驱冷热态对比；
-   动力电池静态基线；
-   直流快充；
-   交流慢充（TM3-016，待完成）；
-   TM3-007 / TM3-008 所覆盖的完整上电、下电过程。

因此，当前工作已经不是零散采集，而是在逐步形成一套车辆的"正常状态空间"。

后续是否增加采集项目，不宜再以"还有什么数据可以采"为主要标准，而应改为：

> **未来诊断电驱或动力电池故障时，还有哪些重要的正常状态或状态转换没有参照基线？**

按照这个标准，后续新增项目应保持克制。

------------------------------------------------------------------------

## 2. 建议补充的基线

### 2.1 持续稳定驱动基线 --- P0

当前已有加速类场景，但加速主要观察：

**请求 → 能力 → 执行 → 反馈**

的动态响应。

建议补充一个干净的稳定驱动场景，例如：

-   平直道路；
-   稳定车速约 30--40 km/h；
-   尽量保持稳定电门；
-   持续一段可供分析的稳定窗口。

主要目的不是重新观察加速，而是回答：

> **系统已经进入稳定驱动以后，各请求、执行、反馈、功率和状态量之间是什么正常关系？**

稳定态基线与加速瞬态基线具有不同的诊断意义。

**建议优先级：P0。**

------------------------------------------------------------------------

### 2.2 加速 → 松电门 → 再加速的连续状态转换 --- P0/P1

目前已有低速加速和低速松电门回收场景。

需要先检查现有采集是否已经包含足够完整的连续过程：

**驱动 → 松电门 → 回收 → 再次驱动**

重点不是增加一个新的孤立状态，而是观察状态转换过程中：

-   请求如何变化；
-   扭矩方向如何变化；
-   回收如何建立和退出；
-   Command / Actual 如何跟随；
-   状态量如何切换；
-   是否存在稳定的时序关系。

如果 TM3-005 或其他现有 ASC
已经完整覆盖这一过程，则**不建议重新采集**，而是在后续分析中把
Transition Evidence 提取出来。

**建议优先级：P0/P1，优先复用已有数据。**

------------------------------------------------------------------------

### 2.3 P / D / R 方向切换基线 --- P1

如果现有"静止挂挡"脚本没有明确覆盖完整的方向状态切换，可考虑补充：

**P → D → P → R → P**

并在每个状态保持足够时间。

该场景可以帮助建立：

-   挡位/方向请求；
-   驱动许可；
-   实际方向状态；
-   扭矩允许/禁止条件；
-   状态转换时序；
-   READY 与 Gear 状态之间的关系。

这是成本较低、风险较低，但对后续诊断比较有价值的状态转换基线。

**建议优先级：P1。**

------------------------------------------------------------------------

### 2.4 不同 SOC 下的动力与回收能力边界 --- 长期积累

不同 SOC 条件下，动力电池允许的：

-   放电能力；
-   充电/回收能力；
-   功率限制；
-   电驱扭矩边界；

可能发生变化。

尤其高 SOC
条件下的回收能力限制，是连接"动力电池能力"与"电驱执行能力"的重要跨系统关系。

但目前**不建议为了制造特定 SOC 条件而专门折腾车辆**。

更合适的方法是：

> 以后车辆自然运行到高、中、低不同 SOC
> 区间时，结合已有标准场景顺手采集并长期积累。

这类数据未来可能比重复采集普通加速更有诊断价值。

------------------------------------------------------------------------

### 2.5 热状态造成的能力边界 --- 长期积累

TM3-013 已经包含电驱冷热态对比，因此目前不建议重复扩展类似采集。

后续如果自然遇到明显不同条件，例如：

-   明显冷车；
-   长时间行驶后的热车；
-   快充后；
-   动力电池温度明显升高；
-   环境温度差异较大的工况；

可以逐渐积累。

真正值得形成基线的不是单纯的温度数值，而是：

**Condition → Capability / Limit → Command / Execution**

之间的正常关系。

------------------------------------------------------------------------

### 2.6 充电完整生命周期与退出过程 --- P1（先检查现有数据）

TM3-015 直流快充和 TM3-016 交流慢充不应只关注稳定充电阶段。

从状态机角度，更完整的生命周期是：

**连接 → 握手/条件确认 → 充电允许 → 功率建立 → 稳定充电 → 降功率/结束 →
退出 → 静置**

因此应先检查现有快充数据是否已经包含：

-   充电开始；
-   功率建立；
-   稳定充电；
-   充电结束或主动停止；
-   退出后的状态恢复。

如果已有 ASC 能够覆盖，就直接分析，不重新采集。

如果现有数据只有稳定充电中段，未来可补充一次完整生命周期。

------------------------------------------------------------------------

## 3. 当前不建议主动扩展的区域

暂时不建议为了"基线完整"而人为制造以下工况：

-   极低 SOC；
-   持续大功率加速；
-   明显过热；
-   打滑；
-   ABS / ESP 强介入；
-   绝缘异常；
-   高压系统故障；
-   人为制造保护触发；
-   其他可能带来车辆或道路安全风险的异常条件。

这些场景虽然具有诊断价值，但已经逐渐从：

**正常基线采集**

进入：

**边界 / 保护 / 异常实验**

的范畴。

后续可在真实工况自然出现、存在真实故障案例，或者具备合适且安全的实验条件时，再单独规划。

------------------------------------------------------------------------

## 4. 建议建立 Baseline Coverage Matrix

当前阶段比继续增加 TM3 编号更重要的一项工作，是逐渐建立：

# Baseline Coverage Matrix

它不是 Signal 清单，而是**诊断状态与状态转换覆盖图**。

### 4.1 电驱状态轴示例

``` text
OFF
 ↓
Wake
 ↓
READY
 ↓
Gear
 ↓
Drive
 ↓
Acceleration
 ↓
Cruise
 ↓
Regen
 ↓
Brake
 ↓
Stop
 ↓
Park
 ↓
Sleep
```

实际车辆过程并非严格单向，应允许状态返回、分支和不同转换路径；以上仅作为覆盖检查的骨架。

### 4.2 动力电池 / 充电状态轴示例

``` text
Rest
 ↓
Wake
 ↓
HV Ready
 ↓
Discharge
 ↕
Regen Charge

DC Charge
    ↓
Charge End
    ↓
Rest

AC Charge
    ↓
Charge End
    ↓
Rest
```

### 4.3 Coverage Matrix 应回答的问题

把已有 TM3 实验映射到这些状态和转换后，应能够快速判断：

-   哪个 TM3 覆盖哪个状态；
-   哪个 TM3 覆盖哪个状态转换；
-   哪些状态已有 ASC；
-   哪些已经完成 Golden Analysis；
-   哪些已经形成 Verified Evidence；
-   哪些只有原始采集尚未分析；
-   哪些是真正没有覆盖的空白；
-   哪些空白值得补采；
-   哪些应转入长期自然积累。

因此后续实验规划应逐渐从：

> **"我还能采什么？"**

转变为：

> **"Coverage Matrix 上还有哪些具有诊断价值的关键状态或转换没有可靠
> Evidence？"**

## 5. 电驱与动力电池基线阶段的建议收官条件

不建议把"覆盖所有可能工况"作为阶段完成标准。

更合理的收官条件是：

> **核心正常状态 + 核心状态转换 +
> 典型能力变化已经覆盖；主要类型均具有经过 Golden Pipeline 审定的
> Evidence 样本；剩余边界条件进入长期自然积累。**

达到这个程度以后，应停止无边界横向扩采。

工作重心转向：

1.  汇总整个采集过程；
2.  审查采集脚本与操作方法；
3.  审查 Golden Analysis Pipeline；
4.  总结不同实验共同产生的稳定知识对象；
5.  区分状态、转换、条件、能力、限制、请求、命令、反馈、结果等语义角色；
6.  形成 Baseline Coverage Matrix；
7.  明确哪些内容属于正常基线，哪些属于边界/保护实验，哪些属于真实故障案例。

------------------------------------------------------------------------

## 6. 与未来 Knowledge Base 的关系

Baseline Coverage Matrix 本身还不是 Knowledge Base。

它首先是未来知识库的：

> **车型基线原料覆盖地图。**

当前阶段最重要的任务仍然是把车型基线的生产过程做稳定，而不是提前设计最终知识库
Schema。

等电驱和动力电池基线采集基本收官、多个不同类型 TM3 实验都经过 Golden
Pipeline 后，再把这些输出摊开比较，回答一个真正决定 Knowledge Base
结构的问题：

> **一个能够被 AI 理解、比较并用于辅助故障诊断的车型
> Baseline，最小需要由哪些稳定知识对象组成？**

未来 Schema 应尽量从真实 TM3 实验和 Evidence
中归纳出来，而不是在采集尚未完成时自顶向下预设一个理想化全集。

------------------------------------------------------------------------

## 7. 当前建议

当前阶段建议：

**完成 TM3-016 慢充 → 检查现有 ASC 对上述状态/转换的实际覆盖 →
只补真正缺失的 P0/P1 基线 → 停止横向扩采 → 做电驱/动力电池基线采集与
Golden Analysis 的阶段性精益总结。**

其中优先检查或补充：

1.  **稳定驱动 / 巡航基线（P0）**
2.  **驱动 → 回收 → 再驱动连续转换（P0/P1，优先复用现有数据）**
3.  **P/D/R 方向状态转换（P1，视 TM3-003 已有覆盖决定）**
4.  **完整充电生命周期与退出过程（P1，优先检查 TM3-015/016 数据）**

SOC、热状态以及各种能力边界不作为当前阶段必须完成项，转入后续长期自然积累。

------------------------------------------------------------------------

**阶段原则：**

> 不以采集数量衡量完整度，而以关键诊断状态、状态转换和 Evidence
> 覆盖衡量完整度。\
> 不为了知识库预设数据，而让未来知识结构从经过 Golden Pipeline
> 审定的真实基线证据中生长出来。
